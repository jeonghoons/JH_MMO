# UEClient/JM/CLAUDE.md

이 문서는 `UEClient/JM/` 디렉토리에서 작업할 때 참고하는 가이드입니다. 프로젝트 전체 구조는 [루트 CLAUDE.md](../../CLAUDE.md)를 참고하세요.

## 빌드 & 실행

빌드는 `ue-build` 스킬을 따릅니다(에디터가 켜져 있으면 Live Coding이 명령줄 빌드를 막음).

프로토콜(생성된 Protobuf 소스)은 `UEClient/JM/Source/JM/Protocol/`에 복사되어 들어옵니다. 이 파일들은 [Common/Protocol/CLAUDE.md](../../Common/Protocol/CLAUDE.md)에서 관리하며, 절대 손으로 수정하지 마세요.

## UE 클라이언트 아키텍처 (`UEClient/JM/Source/JM/`)

- `Network/` — 인게임 레벨은 서버가 정합니다 — 로그인 성공 응답 `SC_LOGIN_INFO_PACKET.map_name`을 받아 `UNetworkManager::EnterGame(MapName)`이 `/Game/Maps/<이름>`을 열고, 이름이 비었거나 레벨이 없으면 들어가지 않고 사유를 띄웁니다(D-185, 클라이언트에 인게임 레벨 이름을 적지 않음).
- 개발용 자동 로그인(D-188, 배포 빌드 제외): `Saved/TestLogin.txt`가 있으면 로그인 화면이 그 계정으로 자동 로그인합니다 — 절차는 `pie-check` 스킬, **끝나면 파일을 지웁니다.**
- 상점 NPC(L4, D-201·D-202): 서버의 `OBJECT_TYPE_NPC`는 플레이어 액터 클래스(`BP_Player`)로 만들어 `Npcs` 맵에 따로 둡니다(몬스터 클래스 `ANpcCharacter`와 무관 — 서버 높이는 지면이라 캡슐 반높이만큼 올림). 판매가 표시는 `FItemTableRow.SellPrice`(**`ItemTable.csv`를 고치면 `reimport_csv`로 `DT_ItemTable`을 다시 채움**), 금액 계산은 서버.
- 포털(L5, D-203): 서버가 방 입장 직후 `SC_PORTAL_LIST`로 쓸 수 있는 포털의 위치·반경을 알려 주고 `UJMObjectManager::Portals`에 둡니다(레벨의 마커 액터는 에디터 전용이라 런타임에 읽지 않음, 도착지는 서버만 앎).
- Room 변경(DG3b, D-216): 마을과 사냥터는 같은 레벨의 서로 다른 서버 Room입니다. 문 포털·사냥터 사망 뒤 부활로 Room이 바뀌면 서버가 `SC_ROOM_CHANGE`를 보내고, `UJMObjectManager::HandleRoomChange`가 **레벨을 다시 열지 않고** 내 캐릭터를 뺀 캐릭터·몬스터·드랍·NPC 액터와 포털 목록을 지운 뒤 내 캐릭터를 받은 자리로 옮깁니다(`OnMyTeleport`). 내 캐릭터는 `Objects`에 남겨 두어 뒤따르는 본인 `SC_ADD_OBJECT`가 무시되고 `SC_REVIVE`가 그대로 동작합니다. 인벤토리 사본은 비우지 않습니다(서버가 다시 보내지 않음). **Room에 딸린 클라이언트 상태를 추가하면 `HandleRoomChange`(오브젝트)·`AJMMyPlayer::ResetForRoomChange`(내 시전·조준·잠금·상호작용 대상)에 정리 코드를 넣습니다.** 이동 거부는 `SC_MOVE_RESULT` → 시스템 메시지.
- 레벨이 바뀌는 Room 변경(DG3c-2, D-226 — 던전 입장·퇴장): `map_name`이 지금 레벨과 다르면 `HandleRoomChange`가 `UNetworkManager::TravelToRoomLevel`을 부릅니다 — 대기 창 "이동하는 중..."을 먼저 띄우고 Tick 두 번 뒤 `SwitchGameMapLevel(레벨, bRoomTravel = true)`(인벤토리·파티 사본을 남김, 서버가 다시 보내지 않음). 새 레벨에서 `AJMPlayerController::BeginPlay`가 보내는 `CS_ENTER_ROOM`이 서버에는 "로딩 끝" 신호입니다(서버는 `LoadTimeoutSec` 60초를 기다림). 내 캐릭터 액터는 레벨과 함께 사라지므로 **레벨 전환 너머로 이어져야 하는 값(보정 순번 = `SC_ROOM_CHANGE.correction_seq`, 공격·조준 순번, 스킬 쿨타임)은 `UJMObjectManager::FRoomTravelCarry`에 담았다가 `HandleSpawn`이 새 액터에 넣습니다(`AJMMyPlayer::GetTravelState`·`ApplyTravelState`) — 그런 상태를 추가하면 이 세 곳에 함께 넣습니다.** 서버는 보정 순번을 0으로 되돌리지 않으므로 빠뜨리면 이동이 전부 버려집니다. 죽은 채 도착하면(본인 `SC_ADD_OBJECT`의 hp 0 — `SC_DEAD`는 다시 오지 않음) 사망 자세와 부활 창을 띄웁니다. 전환 시간은 로그 `[Travel]`에 남습니다.
- 던전 상태(DG3c-2): `SC_DUNGEON_STATE` → `UJMObjectManager::HandleDungeonState` → `UCombatHudWidget::SetDungeonState`(`TxtDungeon`, 클리어 뒤 남은 시간을 1초씩 줄임). 나갈 때 해제 패킷이 없어 `SC_ROOM_CHANGE`마다 지웁니다. 포털 안내 문구는 `PortalInfo.kind`(일반·던전 입구·던전 출구)로 고릅니다.
- 하트비트(`CS_PING`, D-220·D-226)는 **송신 워커 스레드**(`SendWorker::Run`)가 보냅니다 — 게임 스레드가 맵 로딩으로 멈춰도 서버의 유휴 타임아웃에 걸리지 않게. 송신 큐는 생산자 하나(게임 스레드)·소비자 하나(워커) 구조이므로 워커에서 큐에 넣지 않고 소켓으로 직접 보냅니다. 받은 패킷의 처리는 게임 스레드(`UNetworkManager::Tick`)입니다.
- 파티(DG2, D-217·D-224): `UJMPartyManager`(서버가 보낸 `SC_PARTY_STATE`·`SC_PARTY_INVITE`의 사본, 거부·결과 `SC_PARTY_RESULT`는 시스템 메시지)와 `UPartyWidget`/`WBP_Party`(초대 수락·거절 화면 + 파티원 목록·탈퇴 — 파티원 줄은 C++가 `TextBlock`으로 만듦). 입력: 커서 모드(Ctrl)에서 상대를 우클릭한 플레이어 메뉴의 [파티 초대](UI6, D-274 — G·T 키는 없앰), P = 파티 창, 채팅 `/파티초대 이름`·`/파티탈퇴`(`UChatWidget::HandleCommand`가 `/`로 시작하는 입력을 가로챔 — 서버로 채팅을 보내지 않음). 파티원은 다른 Room에 있을 수 있어 이름·레벨·있는 곳을 액터가 아니라 패킷 값으로 그립니다. **파티 사본은 Room 이동·레벨 전환에 비우지 않고 `UNetworkManager::ReturnToLogin`에서만 비웁니다**(던전 레벨 전환 DG3c에도 이어져야 함).
- 경매장(A6.3b D-234, AU2b D-281): `UJMAuctionManager`(서버가 보낸 검색 결과·내 등록·수령함의 사본, 결과 `SC_AUCTION_RESULT` — 성공은 창 안 한 줄·거부는 시스템 메시지)와 `UAuctionWidget`/`WBP_Auction`(탭 네 개 — 목록 줄·필터 버튼은 C++가 `UAuctionRowButton`으로 만듦). 여는 방법이 둘이고 **할 수 있는 일이 다릅니다**: K 키 = 조회 모드(검색·구매·보기), 경매 NPC 앞 F 키 = NPC 모드(등록·취소·수령까지 — `UJMAuctionManager::IsAtNpc()`). NPC가 하는 일은 `ObjectInfo.npc_kind`(상점·경매)로 구분합니다(`UJMObjectManager::GetNpcKind`). **검색(AU2b, D-281)**: 서버는 한 번에 여러 쪽 분량을 주고 매니저가 받은 줄을 모두 쌓아 둡니다(줄 캐시) — 쪽은 캐시를 `page_rows`줄씩 나눈 것이고(`GetPageRange`), 캐시 끝을 넘으면 마지막 줄의 커서로 다음 묶음을 받습니다(`SetPage`). **보고 있는 목록은 다시 받지 않고 구매 응답으로 그 줄만 고칩니다**(끝난 줄은 회색 "판매 완료"). 창을 다시 열어도 검색어·정렬·캐시는 남습니다. 요청 간격은 매니저가 지킵니다 — 검색·새로고침(`CanSearch`, 5초)·정렬/다음 묶음/구매/등록/취소/수령(`CanAct`, 1초)·내 목록(따로 1초, 간격이 풀릴 때 보냄 `FlushMy`): **경매 요청을 보내는 코드를 추가하면 매니저의 `Search`·`Sort`·`SetPage`·`RequestMy`·`Buy`…를 거치게 하고, 버튼은 `CanSearch`·`CanAct`로 끕니다.** 금액은 `JMUIStyle::GoldText`(세 자리 쉼표)로 적습니다. 목록 줄의 열 폭은 `UAuctionWidget::Col*Width` 한 곳(열 머리에도 입힘). 인벤토리 우클릭의 분기 순서는 `UInventoryWidget::OnSlotRightClicked`(장착 칸 해제 → 상점 판매 후보 → 경매 등록 후보 → 거래 제시 → 장착·사용) — 인벤토리에서 아이템을 고르는 창을 추가하면 여기에 넣고 다른 창과 함께 열리지 않게 합니다. 수령함 알림(`SC_MAIL_NOTICE`, D-262·D-265)은 `UJMAuctionManager::HandleMailNotice` → 시스템 메시지·채팅 한 줄·`HasMailNotice()`(HUD `TxtMail`) — 표시는 레벨 전환에 남고 수령함 목록(`SC_AUCTION_MY`)이 비어서 오면 내려갑니다.
- 퀘스트(Q1, D-261·D-264·D-265·D-266): `UJMQuestManager`(서버가 보낸 내 퀘스트의 사본 — `SC_QUEST_LIST`는 첫 입장 때만 오므로 **Room 이동·레벨 전환에 비우지 않고 `ReturnToLogin`에서만 비움**, 레벨 전환 때는 창 열림 상태만 `ResetWindow`)와 `UQuestWidget`/`WBP_Quest`(창 하나 — 줄 버튼은 C++가 `UAuctionRowButton`으로 만듦 — 퀘스트 NPC(`npc_kind` 3) 앞 F = 대화 모드 [수락]/[완료], L 키 `IA_Quest` = 목록 모드). 요청은 `CS_QUEST_REQUEST` 하나이고 수락·완료는 서버가 상태로 정합니다. 수집형 진행은 서버가 0을 보내므로 인벤토리 수량으로 그립니다. 글자·목표 수는 `DT_QuestTable`(`QuestTable.csv`를 고치면 `reimport_csv`). 마을 NPC 머리 위 이름표·표식(`UNameplateWidget` — `UJMObjectManager`가 NPC를 만들 때 화면 공간 `UWidgetComponent`를 붙임)과 HUD 진행 줄(`TxtQuestTracker`)은 `OnQuestChanged`로 다시 그립니다. HUD의 진행 줄·수령함 줄·알림 줄은 `WBP_CombatHud`의 `TxtQuestTracker`·`TxtMail`·`TxtNotice`입니다. 수락·목표 달성·완료처럼 확인이 필요 없는 안내는 **`UJMUIManager::ShowNotice`**(화면 위쪽 가운데에 몇 초 떴다 사라지는 줄 — 시간·줄 수는 `WBP_CombatHud`의 `NoticeDurationSec`·`NoticeMaxLines`)를 쓰고, 확인 버튼이 있는 `ShowSystemMessage`는 거부·오류에만 씁니다. **이름표만 WBP 없이 C++가 배치를 만듭니다** — 위젯 컴포넌트가 만든 위젯은 PlayerContext가 없어 `NativeOnInitialized`가 불리지 않으므로 `Initialize`에서 만듭니다. ## 에디터 MCP (Epic 공식 `ModelContextProtocol`)

에디터가 켜지면 `http://127.0.0.1:8000/mcp`가 자동으로 시작되고(`Config/DefaultEditorPerProjectUserSettings.ini`), 저장소 루트 `.mcp.json`의 `unreal` 서버로 연결됩니다(Claude Code는 에디터가 켜진 뒤 시작하거나 `/mcp`로 재연결). 도구는 `list_toolsets` → `describe_toolset` → `call_tool` 순서로 찾아 부릅니다.
- 공식 툴셋 함정: `SceneTools.load_level`은 현재 레벨이 저장돼 있어야 하고, `EditorApp.CaptureViewport`는 `captureTransform`·`annotations`를 값으로 줘야 합니다(실제 PIE는 `StartPIE`/`StopPIE`, 그래프 편집은 Blueprint `write_graph_dsl`).
- 프로젝트 툴셋 `jm_mcp`(`Content/Python/jm_mcp/toolset.py`, `Content/Python/init_unreal.py`에서 등록): `KitTools`(jm_kit 함수), `DataTableReimportTools.reimport_csv`(CSV 재임포트, 새 DT는 `create_from_csv`), `AnimBuilderTools`, `WorldTools`, `RetargetTools`.
- 공식 도구로 안 되는 작업의 순서: ① jm_kit 함수 + `jm_mcp` 툴셋 추가(에디터 재시작) ② 그래도 안 되면 `JMEditorTools`에 임시 커맨드렛 → `UnrealEditor-Cmd.exe <uproject> -run=<Name> -unattended -nopause`(에디터를 닫고, 필요한 모듈은 `Build.cs`에 임시 추가, 끝나면 커맨드렛·`Build.cs`를 되돌리고 다시 빌드). 어느 경우든 먼저 덤프로 현재 상태를 확인하고(사용자가 일부를 이미 해 뒀을 수 있음) 수정 전에 에셋을 백업합니다.
- 서버에 인증이 없으므로 **임의 Python 실행 도구는 두지 않습니다**. 새 자동화가 필요하면 jm_kit 등에 함수를 만들고 `jm_mcp` 툴셋에 감싸 추가합니다. 툴셋 인자는 `X | None = None` 형식(`Optional[X]`는 등록 실패). 툴셋을 고친 뒤에는 에디터를 다시 시작해야 반영됩니다(`KitTools.reload_kit`는 jm_kit만 다시 불러옴).

## 알려진 함정 (Gotcha)

- **소스 인코딩**: 한글 주석이 있는 C++ 파일은 UTF-8 **BOM을 유지**합니다(BOM 없는 UTF-8이면 MSVC가 다음 줄을 삼킬 수 있음, `JMEditorTools/*.cpp`는 예외로 BOM 없이도 컴파일됨). CP949 파일은 Edit 도구가 거부하므로 바이트 단위로 고칩니다(2026-11-21 확인: `JMUIManager.*`·`JMPlayerController.cpp`·`NetworkManager.cpp`를 포함해 `Network/`·`Game/`·`Player/`·`UI/`의 고친 파일은 모두 UTF-8이었음 — 고치기 전에 인코딩을 한 번 확인). Bash 히어독으로 한글을 넘기면 CP949로 깨지므로, 한글이 든 스크립트는 파일로 만든 뒤 `python -I -X utf8`로 실행합니다.
- **빌드**: 에디터가 켜져 있으면 Live Coding 때문에 명령줄 빌드가 막힙니다 — 순서는 `ue-build` 스킬(`.claude/skills/ue-build`).
- **위젯 블루프린트 C++ 조작**(커맨드렛, UE 5.6에서 확인): 새 위젯은 변수 여부와 관계없이 **모두** `WidgetBP->OnVariableAdded(Name)`로 GUID를 등록해야 컴파일 ensure가 나지 않습니다. 삭제는 `WidgetTree->RemoveWidget` → `Rename(nullptr, GetTransientPackage())` → `OnVariableRemoved` 순서. WBP 생성은 `FKismetEditorUtilities::CreateBlueprint(Parent, Package, Name, BPTYPE_Normal, UWidgetBlueprint::StaticClass(), UWidgetBlueprintGeneratedClass::StaticClass())`, 텍스처 가져오기는 `UAssetImportTask` + AssetTools(`Build.cs`에 `AssetTools`, 위젯이면 `UMG`·`UMGEditor`·`Slate`·`SlateCore` 임시 추가).
- **BP 기본값을 MCP로 고친 뒤에는 컴파일 필수**: `ObjectTools.set_properties`로 블루프린트 CDO(`Default__X_C`)를 바꾸면 CDO에는 값이 보이지만, 새 인스턴스는 **마지막 컴파일 때 C++ 부모와 다르다고 기록된 속성만** 복사하므로 값이 빠진 채 생성된다(2026-11-16 `BP_MyPlayer.QuickSlotActions`가 PIE에서 빈 배열, 11-15 `BP_TestPlayer.AutoScript`도 같은 원인). 바꾼 뒤 `BlueprintTools.compile_blueprint` → 저장하고, 확인은 CDO가 아니라 새로 배치한 인스턴스 값으로 한다.
- **GameMode 상속 확인**: 맵이 쓰는 GameMode가 C++ 클래스를 실제로 상속하는지 먼저 봅니다(2026-10-28 `BP_GameMode`의 부모가 엔진 `GameModeBase`라 HUD 등록 코드가 실행되지 않았음).
- **MCP 연결**: 세션 시작 때 `unreal` MCP 연결이 실패해도 에디터 서버(127.0.0.1:8000)는 살아 있을 수 있습니다 → JSON-RPC(`initialize` → `tools/call` `call_tool`)로 직접 호출할 수 있습니다.
- **백그라운드 스로틀**: 에디터가 뒤에 있으면 "Use Less CPU when in Background"로 프레임이 초당 3~4로 떨어지고 GPU 파티클·풀이 진행되지 않습니다 — 측정·촬영 전에 `ObjectTools.set_properties("/Script/UnrealEd.Default__EditorPerformanceSettings", {"bThrottleCPUWhenNotForeground": false})`(또는 `Saved/Config/WindowsEditor/EditorSettings.ini`의 같은 값, 로컬)로 끄고 끝나면 되돌립니다.
- **사용자 안내**: 에디터 수동 작업을 안내할 때는 UE 5.8 UI 이름을 기준으로 합니다. 사용자가 "그 항목이 없다"고 하면 5.8에서의 표시 위치를 설명합니다. 안내에 포함할 것: 애셋 종류와 부모 클래스, 저장 경로·이름, 에디터 조작 순서, 설정할 프로퍼티와 값, 다른 곳에 연결하는 방법, 완료 확인 방법, C++가 Blueprint에 노출하는 프로퍼티/함수(루트 CLAUDE.md "작업 절차 규칙" 5).
