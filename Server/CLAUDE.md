# Server/CLAUDE.md

이 문서는 `Server/` 디렉토리에서 작업할 때 참고하는 가이드입니다. 프로젝트 전체 구조는 [루트 CLAUDE.md](../CLAUDE.md)를 참고하세요.

## 빌드 & 실행

빌드·실행·종료 절차는 `run-server` 스킬에 있습니다. 솔루션(`Server/Server.sln`, 구성 `Debug|Release` × `x64|x86`)의 다른 실행 프로젝트는 `msbuild Server.sln /p:Configuration=Debug /p:Platform=x64 /t:LoadTest`(`/t:DummyClient`·`/t:NavGenerator`)로 빌드합니다.

- `GameServer` (`Server/Server/Server.vcxproj`) — 실제 게임 서버, 진입점은 `gameserver.cpp`.
- `BotEngine` (`Server/BotEngine/`, 정적 라이브러리) — LoadTest와 DummyClient가 공유하는 봇 엔진. 봇은 클라이언트 측이라 ServerCore를 쓰지 않습니다(DECISIONS 2026-10-30). 프로토콜은 `Server/Server/Protocol/`의 생성 코드를 직접 컴파일하므로 `GanPackets.bat` 뒤에 따로 복사할 것이 없습니다. 새 패킷을 봇이 보내거나 받아야 하면 `BotEngine.cpp`의 `HandlePacket`/`WorkerMain`에 추가합니다.
- `LoadTest` (`Server/LoadTest/`) — BotEngine의 헤드리스 콘솔 프런트엔드. 수치 검증용. 사용법은 [Docs/TESTING.md](../Docs/TESTING.md) 참고.
- `DummyClient` (`Server/DummyClient/`) — BotEngine의 OpenGL 시각화 프런트엔드(시연용). 창을 닫을 때까지 실행. 사용법은 [Docs/TESTING.md](../Docs/TESTING.md) 참고.
- `NavGenerator` (`Server/NavGenerator/`) — Recast/Detour 내비메시 데이터를 오프라인으로 생성하는 도구. **UE에서 맵 지오메트리를 다시 export할 때마다 재실행해야 합니다**(실행법·출력·검증용 `--query` 모드는 `nav-export` 스킬). **`NavmeshManager::CanMove`를 고치면 `NavQuery.cpp`의 `move`도 같이 고칩니다**(두 프로젝트가 코드를 공유하지 않음). 지오메트리는 `Server/MapResource/MapExport.bat <맵>`(UE 커맨드렛 `MapExportCommandlet` → NavGenerator)으로 만들며, **UE에서 캐릭터가 부딪히는 메시와 지형(스태틱메시·ISM·Landscape, 충돌 켜짐 + Pawn Block)만** Detour 좌표(UE (x,y,z) → (y,z,-x), 정점 순서 반대)로 내보냅니다 — 서버 이동 검증이 이 내비메시를 쓰므로 기준이 어긋나면 지나갈 수 있는 곳에서 플레이어가 끌려갑니다(2026-10-30 S1).

서버에는 자동화된 테스트 스위트가 없습니다 — 검증은 `GameServer`를 빌드해서 `LoadTest`/`DummyClient`나 UE 클라이언트로 붙여보는 방식으로 합니다.

프로토콜(생성된 `.pb.h`/`.pb.cc`)은 `Server/Server/Protocol/`에 복사되어 들어옵니다. 이 파일들은 [Common/Protocol/CLAUDE.md](../Common/Protocol/CLAUDE.md)에서 관리하며, 절대 손으로 수정하지 마세요.

## 서버 아키텍처

**계층과 폴더 (2026-10-30 C-5)** — 의존은 GameServer → ServerCore 한 방향입니다.
- **ServerCore는 Protocol·게임 헤더를 include하지 않습니다.** 게임이 필요하면 가상 훅(`Session::OnConnected/OnDisconnected/OnRecvPacket`)이나 주입(`ServerService`의 `SessionFactory`)으로 연결합니다.
- `#include`는 프로젝트 루트 기준 경로로 씁니다(`"Network/Session.h"`, `"Game/Room/Room.h"`). GameServer의 include 경로는 `$(ProjectDir)`와 `$(SolutionDir)ServerCore`이므로 **두 프로젝트에 같은 파일 이름을 만들지 않습니다.** 새 파일은 vcxproj와 `.filters`에 같은 폴더로 추가합니다.

- **Job/JobQueue 패턴** (`Job.h`, `JobQueue.h`): 서버의 동시성 모델입니다. 여러 IOCP 워커 스레드에서 안전하게 접근해야 하는 객체(실제로는 `Room`)는 `JobQueue`를 소유하고, 그 큐에서 실행되는 `Job` 안에서만 자기 상태를 변경합니다(`Room::PushJob` / `Room::ReserveJob`).
- **송신 묶기 (P1b, D-206·D-207)**: 잡 큐(Room·로비)의 작업을 실행 중인 스레드에서 부른 `Session::Send`는 바로 `WSASend`하지 않고 세션 송신 큐에 넣은 뒤 그 잡 큐의 "보낼 세션 목록"(`JobQueue::_pendingSends`, `Session::_flushPending`으로 중복 방지)에 자동 등록됩니다(`JobQueue::Current()` — 잡 큐 밖 스레드의 `Send`는 지금처럼 바로 보냄). **주의**: ① 방 작업 안에서 보낸 패킷은 최대 `SendFlushIntervalMs` 늦게 나갑니다 — 보낸 직후 `Disconnect`하면 버려지므로 끊기 전에 꼭 보내야 하는 패킷은 `Session::ForceClose`(끊기 전에 전송을 걸고 `Disconnect`)를 씁니다. ② **잡 큐(Room)를 없앨 때는 먼저 그 큐의 보낼 세션 목록을 모두 내보내야 합니다** — 목록에 남은 세션은 `_flushPending`이 켜진 채 남아 이후 송신이 조용히 멈춥니다(2026-11-19 리뷰). 닫기 절차는 `JobQueue::CloseSendBatch()`(그 큐의 작업 안에서 호출 — 간격 0·깨우기 해제 뒤 목록 전부 내보냄, 이후 그 큐의 `Send`는 작업 끝에 바로 나감)이고 `Room::Close`가 부릅니다(아래 "Room 닫기"). 잡 큐를 가진 다른 객체를 없애는 코드를 넣으면 같은 호출이 필요합니다. 지표는 `[metrics]`의 `sendCalls/s`·`bufsPerSend`·`sendPath`·`flushGap`·`sendWake`·`jobWait`(설명 [Docs/TESTING.md](../Docs/TESTING.md) "부하 테스트 하니스").
- **시전 요청·거부 알림 (CP1, D-211·D-213)**: 거부는 `Room::CastSkill`의 `reject` 람다가 플레이어 본인에게만 `SC_ATTACK_RESULT`로 알립니다. 클라이언트는 내 시전을 입력 즉시 시작하고 이 패킷으로 되돌리므로, **`CastSkill`에 거부 조건을 추가하면 조용히 `return`하지 말고 `reject(사유)`를 부릅니다**(빠지면 클라이언트가 2초 동안 다음 시전을 못 보냄). 몬스터는 `seq` 0·허용 오차 0. 봇은 `CS_ATTACK`에 순번을 싣고 거부를 사유별로 셉니다(LoadTest 요약 `[summary] attack:`) — 사냥 봇은 쿨타임을 보지 않아 요청의 약 77%가 거부됩니다(정상).
- **연결 정리 (A5.0, D-220·D-221)**: `Session::Disconnect`는 세션당 한 번만 동작하고 `OnDisconnected` → 세션 목록에서 빼기 → **`shutdown(SD_BOTH)` + `CancelIoEx`** 순서입니다(감사 F4 — 걸려 있던 `WSARecv`·`WSASend`가 세션 참조를 쥐고 있어, 취소하지 않으면 받지 않는 클라이언트의 세션·소켓·송신 큐가 남음). 서버가 스스로 끊는 조건 둘: ① **유휴 타임아웃** — 무엇이든 받으면 `Session::_lastRecvMs`를 갱신하고(`ProcessRecv`), `AuthLobby::CheckIdleSessions`(로비 예약 잡, 5초마다 자기 재예약)가 `ServerService::CloseIdleSessions`로 `[Network] IdleTimeoutSec`(60초, 0 = 끔) 동안 수신이 없던 세션을 끊습니다(로그인 전 연결 포함, 대상을 락 안에서 모으고 락 밖에서 끊음 — `Disconnect`가 `ReleaseSession`의 쓰기 락을 잡음). UE 클라이언트는 5초마다 `CS_PING`(하트비트), 봇은 방에 들어간 뒤 `--ping-interval`(1초)마다 보냅니다 — **클라이언트가 한동안 아무것도 보내지 않는 절차(긴 로딩 등)를 만들면 이 시간보다 짧은지 확인합니다.** ② **송신 큐 상한** — `Session::Send`가 큐에 넣은 뒤 쌓인 수가 `[Network] SendQueueLimit`(4000, 0 = 끔)을 넘으면 WARN 로그를 남기고 끊습니다(핑은 보내면서 받지 않는 클라이언트). 지표 `[metrics] conn(sessionObjs/handles idleKick/sendqKick)`: `sessions`는 `Disconnect` 순간 줄어들므로 끊긴 세션이 실제로 사라졌는지는 `sessionObjs`(살아 있는 `Session` 객체 수 — 바닥은 1, Listener가 다음 접속용을 하나 미리 만듦)·프로세스 핸들 수·`sendQ(total)`로 봅니다.
- **세션 & 패킷**: `GameSession::GetPlayer()`/`SetPlayer()`는 `atomic<shared_ptr>`(로비 잡이 넣고 수신 스레드·`Disconnect`를 부른 스레드가 읽음), 플레이어의 방 `GameObject::GetCurrentRoom()`/`SetOwnerRoom()`은 `atomic<weak_ptr>`입니다. **핸들러 안에서는 한 번만 읽어 지역 변수로 씁니다**(A5.0, 감사 F3·F9).
- **전역 서비스·채널 (DG3a, D-215·D-222, 설계 [Docs/DESIGN_PARTY_DUNGEON.md](../Docs/DESIGN_PARTY_DUNGEON.md) §2·§3)**: `WorldService`(`Game/World/WorldService`, 전역 `GWorld`)가 접속자 명부·채널·채널의 Room을 맡습니다. `AuthLobby`와 같은 꼴(자체 잡 큐, 상태는 서비스 잡 안에서만 — 밖에서는 `GWorld->PushJob`)입니다. **순서 규칙**: 서비스 큐는 넣은 순서대로 실행하므로, 로비는 `RegisterPlayer`를 **`session->SetPlayer` 앞에서** 넣습니다 — 입장 요청·정리 신호는 세션에 플레이어가 보인 뒤에만 큐에 들어가 항상 등록보다 뒤에 실행됩니다(순서를 바꾸면 등록 전에 정리 신호가 지나가 명부에 항목이 남음). 명부 키는 세션 id(= 오브젝트 id, 재사용 안 됨 — 더미 봇은 전원이 한 PlayerUID)이고 정리 신호는 두 번 와도 됩니다. Room은 정체 `RoomInfo{roomId, kind(Town/Field/Dungeon), channel, area, levelName}`를 갖고(`Room::GetInfo()`, 만들 때 정하고 불변) 레벨 수치는 `Room::GetWorldData()`(그 레벨의 `WorldTable` 행)에서 읽습니다 — **Room 안의 코드는 `GServerConfig.mapName`을 읽지 않습니다**(그 값은 "로그인한 플레이어가 처음 들어가는 레벨"의 뜻으로 `gameserver.cpp`의 행 확인·로그인 응답 `map_name`·`WorldService`의 채널 Room 생성·방 배정 전의 `Player::CurrentWorldData()`에서만 씀). 지표 `[metrics] world(channels/roster/chMax)` — 접속이 모두 끝난 뒤 `roster`·`chMax`가 0이 아니면 정리 신호가 빠진 경로가 있는 것입니다.
- **구역별 Room·Room 간 이동 (DG3b, D-216·D-223, 설계 [Docs/DESIGN_PARTY_DUNGEON.md](../Docs/DESIGN_PARTY_DUNGEON.md) §2-3·§4)**: 레벨의 마커에 구역 이름(`area` = `town`/`field`)이 있으면 `WorldService`가 채널마다 **마을 Room(`AREA_TOWN`)과 사냥터 Room(`AREA_FIELD`)** 을 따로 만듭니다(없는 레벨은 Room 하나, `area` 빈 글). `GameMap`은 마커를 레벨 전체로 보관하고(포털의 도착 마커는 다른 구역에 있음) **쓰는 쪽이 `GameMap::InArea(marker.Area)`로 거릅니다** — 스폰·NPC·포털 목록·시작 지점(`Room::PickStartPosition`: 구역의 PlayerStart를 차례대로 + 반경 3m)·안전 구역(`IsInSafeZone`). 마커를 쓰는 코드를 추가하면 이 검사를 넣습니다. 처음 입장은 마을 Room이고, 이동은 문 포털(`ResolvePortalTarget`이 `PortalRoute::OtherRoom`)과 사냥터 사망 뒤 부활(`PlayerRevive`)입니다. 순서: `Room::BeginMove`(② 확정 전 거래 취소 `MOVED` + 대기) → `TryAdvanceMove`(③ `Player::HasUnfinishedWork()`가 false면 이동 표시) → `WorldService::RequestMove`(④) → 출발 Room `OnMoveResolved`(⑤ 다시 검사하고 방에서 뺀 뒤 **`SetOwnerRoom(도착)` → 도착 Room에 잡**) → 도착 Room `PlayerArriveRoom`(⑥⑦ `SC_ROOM_CHANGE` → 본인 `SC_ADD_OBJECT` → `SC_PORTAL_LIST` → 부활이면 본인 `SC_REVIVE` → 시야) → `WorldService::OnPlayerMoved`(⑧). **규칙 둘**: ① **`Player`의 필드는 그 플레이어의 소유 Room(`GetCurrentRoom()`) 잡에서만 만집니다** — 옛 Room에 도착한 퇴장 잡은 소유 Room으로 넘기고(`PlayerLeaveRoom`), 몬스터처럼 플레이어 포인터를 들고 있는 코드는 자기 Room 데이터(시야 목록)로 먼저 거른 뒤 필드를 읽습니다(`Monster::IsTargetable`). ② **DB 결과는 요청한 Room으로 돌아오므로 떠나기 전에 DB에 가 있는 작업이 0건이어야 합니다** — 이동 대기·이동 표시 중(`Player::roomMove.Active()`)에는 새 DB 작업을 시작하지 않습니다(`CheckItemRequest`·장착·액티브 칸·거래 신청은 `BUSY`, `RequestProgressSave`·`RequestQuickSlotSave`는 미룸). **플레이어의 DB 작업을 새로 추가하면 `HasUnfinishedWork()`에 넣고, 시작하는 곳에서 `roomMove.Active()`를 보고, 결과 처리 끝에서 `TryAdvanceMove`를 부릅니다.** 이동 입장은 처음 입장과 달리 보정 순번을 +1만 하고(0으로 되돌리면 클라이언트 이동이 전부 버려짐) 쿨타임·포털 재사용 대기를 잇고 `SC_INVENTORY`를 다시 보내지 않습니다. 지표 `[metrics] roomMove(total start/done/reject/timeout/cancel abortBusy/orphan/ownerBad)` — **뒤의 셋은 0이어야 정상**(떠나기 직전에 DB 작업이 남음 / DB 결과가 옛 Room으로 옴 → 그 접속을 끊음 / 소유 Room 불일치), `kind(town/field players)`·`tickLateP99(town/field)`. 시험 키 `[Debug] AllowDummyLogin`(봇 `is_dummy` 로그인 허용 — 기본 꺼짐, D-291)·`DummyRoom`(더미 봇이 처음 들어가는 Room, `spread` = 마을·사냥터 스폰 지점에 고르게 — D-292. 더미의 체형·장비는 로그인 때 메모리에서 무작위 — D-294)·`MoveHandoffDelayMs`(이동 잡 사이를 늦춤)와 시험 스크립트는 `load-test` 스킬.
- **Room 닫기 (DG3c-1, D-225, 감사 F8)**: `Room::ReserveJob`으로 예약한 작업은 Room을 **약한 참조**로 잡고, 예약할 때와 실행할 때 닫힘(`Room::IsClosed`)을 봅니다 — 예약만으로는 Room이 살아남지 않고, 닫힌 방에서는 틱 재예약(`Update`)·스킬 판정·지연 피해·몬스터 스폰/제거·드랍 소멸이 모두 멈춥니다. **닫힌 뒤에도 반드시 돌아야 하는 예약은 `ReserveJobAlways`**(강한 참조 — 지금은 Room 이동의 인계 지연 두 곳뿐. 이 작업이 버려지면 플레이어가 어느 방에도 없는 채 남음)를 씁니다. `PushJob`으로 오는 작업(늦게 온 퇴장·DB 결과·파티 번호)은 닫힌 방에서도 평소대로 돕니다. `Room::Close`(서비스가 넣는 Room 잡, 플레이어·로딩 대기 0명일 때만): 닫힘 표시 → 몬스터·드랍·장판·NPC 비우고 전역 지표(`Metrics::Monsters`·`Drops`) 감소 → `JobQueue::CloseSendBatch()` → `RoomManager::Remove`. Room을 잡고 있는 것은 서비스의 목록(`Channel`·`Instance`)과 `RoomManager`뿐이라 닫으면 큐에 남은 작업이 끝나는 대로 소멸합니다. 예약 없이 불릴 수 있는 `CreateDrop`·`CreateZone`·`SpawnMonster`는 닫힘을 직접 봅니다 — **Room에 오브젝트를 만드는 함수를 추가하면 같은 검사를 넣고, `Close`에서 비우는 목록에도 넣습니다.** 지표 `[metrics] roomsAlive`(살아 있는 `Room` 객체 수) — **`rooms`(보관소의 수)와 같아야 정상**입니다(다르면 닫은 Room을 누가 잡고 있음).
- **인스턴스 던전 (DG3c-1, D-218·D-225, 설계 [Docs/DESIGN_PARTY_DUNGEON.md](../Docs/DESIGN_PARTY_DUNGEON.md) §4·§6)**: 던전 레벨(`WorldTable.LevelKind` = `dungeon`)은 채널 Room이 아니라 **인스턴스 Room**(`RoomKind::Dungeon`, 구역 이름 `AREA_DUNGEON`, 인스턴스 id = `roomId`)으로만 엽니다. 목록·소유·자리는 `WorldService::_instances`(`Instance{room, ownerPartyId 또는 ownerSessionId, cleared, ejecting, members}`)가 맡고 서비스 잡 안에서만 만집니다. **`members` = 자리를 잡은 세션(들어오는 중 + 안에 있음)이고 0이 되면 바로 닫습니다**(`LeaveInstance` → `CloseInstance` → `Room::Close`, 60초 유지 없음 — 다시 들어가면 새 인스턴스). 자리는 `RequestMove`가 승인할 때 잡고(`JoinInstance`), 돌려주는 경로는 셋입니다: 출발 Room에서 이동이 취소됨(`Room::OnMoveResolved`의 모든 취소 분기 → `WorldService::OnMoveAborted`), 던전에서 나와 다른 Room에 도착(`OnPlayerMoved`), 접속 종료(`OnPlayerClosed`). **이동을 취소하는 분기나 명부 항목을 지우는 경로를 추가하면 자리 반납을 함께 넣습니다** — 빠지면 인스턴스가 닫히지 않습니다(`[metrics] dungeon(now/created/closed players)`: 접속이 모두 끝난 뒤 `now`가 0, `created` = `closed`여야 정상).
  - **이동 요청**: 출발 Room은 `MoveRequest`(`ChannelArea` = 내 채널의 구역 Room / `LevelPortal` = 다른 레벨 포털 / `Instance` = 정해진 인스턴스)를 보내고 서비스는 `MoveGrant{dest, result, instanceId, followers}`로 답합니다. 다른 레벨로 가는 포털은 `targetMap`이 `WorldTable`에 있을 때만 받고(정거장 110은 계속 `NOT_AVAILABLE`), 던전 입구의 판정은 `WorldService::ResolveDungeonEnter`(혼자 = 1인 인스턴스, 파티 = 인스턴스가 있으면 누구나 합류·없으면 파티장만 생성 `NOT_LEADER`, 클리어한 인스턴스 `DUNGEON_CLEARED`, 상한 `[World] MaxDungeonInstances` `DUNGEON_FULL`)입니다. 파티장이 들어가면 같은 Room의 파티원을 `followers`로 돌려주고 출발 Room이 파티장을 보낸 뒤 각자에게 `BeginMove(Follow)`를 겁니다(전투·거래 중·사망이어도 감, 이미 이동 중이거나 DB 작업이 5초 넘게 안 끝나면 그 사람만 남음). 던전 출구는 `LevelPortal`(시작 레벨·포털 100)이고 서비스가 그 마커의 구역 Room(사냥터)을, 도착 Room이 마커 바로 밖 자리(`PickPositionNearPortal`)를 정합니다.
  - **로딩 대기**: 출발 Room이 떠날 때 `roomMove.crossLevel`(도착 레벨이 다름)을 적고, 도착 Room의 `PlayerArriveRoom`은 `SC_ROOM_CHANGE`만 보낸 뒤 `Room::_loading`에 둡니다(`_players`·`_objects`·시야 밖 — 방송·전투·요청 처리가 모두 `_players` 기준이라 따로 막을 것이 없음). 클라이언트가 레벨을 열고 **`CS_ENTER_ROOM`**(방이 이미 있는 플레이어의 요청 = 로딩 끝 신호 → `Room::PlayerLoadDone`)을 보내면 `FinishArrive`(본인 `SC_ADD_OBJECT` → `SC_PORTAL_LIST` → 던전이면 `SC_DUNGEON_STATE` → 시야 → `OnPlayerMoved`)로 마칩니다. `[World] LoadTimeoutSec`(60)을 넘기면 끊고(`UpdateLoading`), 대기 중 끊기면 `PlayerLeaveRoom`의 "방에 없음" 분기가 목록에서 빼고 마지막 저장을 요청합니다. **`_players`에 없어도 이 Room이 가진 플레이어가 있다는 뜻이므로, "방에 사람이 없다"를 보는 코드는 `_loading`도 봅니다**(`Room::Close`).
  - **던전 규칙**: `SpawnTable.RespawnSec` -1 = 다시 나오지 않음(`Room::RemoveMonster`). 우두머리 = 던전 Room에서 구역 이름 `boss`(`ZONE_BOSS`)인 스폰 — 전부 죽으면 `Room::OnBossDead`가 전원에게 `SC_DUNGEON_STATE(CLEARED, 남은 초)`를 보내고 서비스가 `WorldTable.DungeonClearExitSec` 뒤 `Room::EjectAll`로 마을에 내보냅니다. 던전에서 죽으면 같은 Room의 시작 지점에서 부활합니다(`PlayerRevive`의 방 안 분기). 서버가 내보내는 이동은 `Room::EjectPlayer`(`MoveReason::Eject` — 대기 시한을 넘겨도 취소하지 않고 계속 기다림, 다른 이동의 응답 대기 중이면 `Player::ejectPending`으로 미룸)이고, 사유는 본인에게 알리지 않습니다(`Follow`·`Eject`는 본인이 요청한 이동이 아님).
  - **파티 연동**: 인스턴스에 자리가 있는 사람은 초대할 수도 초대받을 수도 없습니다(`PARTY_RESULT_IN_DUNGEON`). 인스턴스 안에서(들어가는 중 포함) 탈퇴하면 마을로 내보내고(`RemoveFromParty` → `EjectFromInstance`), 이동·로딩 중이라 아직 방에 없으면 도착했을 때 `OnPlayerMoved`가 자격(주인 파티의 구성원인가·내보내는 중이 아닌가)을 다시 봐서 내보냅니다. 한 명 남아 해산되면 인스턴스의 주인은 그 사람(안에 자리가 있을 때)으로 바뀝니다.
  - 시험 키 `[Debug] PortalNoRange`(포털 거리 검사 생략)와 시험 스크립트·봇 옵션(`--dungeon`)은 `load-test` 스킬.
- **파티 (DG2, D-217·D-224, 설계 [Docs/DESIGN_PARTY_DUNGEON.md](../Docs/DESIGN_PARTY_DUNGEON.md) §5)**: 파티는 Room 상태가 아니라 `WorldService`의 상태입니다(`_parties`·`_invites`, 구성원 = 세션 id). 패킷 핸들러(`CS_PARTY_INVITE`·`RESPOND`·`LEAVE`)는 Room을 거치지 않고 `GWorld->PushJob`으로 넘기고, 서비스가 세션에 직접 `SC_PARTY_INVITE`·`SC_PARTY_STATE`(바뀔 때마다 전원, 구성원 0명 = 파티 없음)·`SC_PARTY_RESULT`를 보냅니다. Room이 알아야 하는 것은 **`Player::partyId` 사본 하나**(드랍 소유권 `DropItem::CanPickup` — 막타 본인 또는 줍는 순간 같은 파티)이고, 서비스가 `WorldService::SetPartyId` → `Room::SetPlayerParty(player, partyId, seq)`로 소유 Room 잡에 알립니다(받은 Room이 소유 Room이 아니면 넘기고, `seq`가 더 큰 것만 적용 — **서비스는 `Player` 필드를 직접 쓰지 않습니다**). 탈퇴·접속 해제는 `RemoveFromParty` 한 곳(파티장이면 맨 앞 사람에게 위임, 한 명 남으면 해산)이고, 접속 해제는 `OnPlayerClosed`에서 대기 초대 삭제(`DropInvitesOf`)와 함께 부릅니다. Room 이동 도착(`OnPlayerMoved`)에서 파티원이면 상태를 다시 보냅니다(있는 곳 표시). **명부 항목을 지우는 경로를 추가하면 파티·초대 정리를 함께 부릅니다.** 지표 `[metrics] party(now parties/members/invites total invite/accept/decline/timeout/reject created/disbanded)` — **접속이 모두 끝난 뒤 앞의 셋이 0이 아니면 정리가 빠진 것**입니다. 수치는 `EconomyTable`의 `PartyMaxMembers`·`PartyInviteTimeoutSec`. 던전 관련 규칙(`IN_DUNGEON`·인스턴스 소유·탈퇴 시 내보냄)은 위 "인스턴스 던전". 봇은 받은 초대를 모두 수락하고 `--party-size N`·`--party-churn-sec S`로 파티를 맺고 탈퇴를 반복합니다(시험 스크립트는 `load-test` 스킬).
- **월드 모델·시야(AOI)**: 각 `Room`은 자신의 `GameMap`(`AoiIndex` — 시야는 거리로 판정: 들어옴 ≤ R, 나감 > R+H, 수치는 `WorldTable.csv`)과 `NavmeshManager`를 소유합니다. **위치를 바꾸면 이동이 끝난 뒤 반드시 `UpdateMap`(플레이어 `PlayerMove`, 몬스터 `NPCMove`)을 불러야 합니다** — 늦게 부르면 AOI가 옛 위치를 들고 경계에서 판정이 틀립니다(`[Debug] ViewAudit`로 확인).
- **영속성(Persistence)**: 연결 문자열은 `ServerConfig.ini`의 `[Database] ConnectionString`(기본 `Driver={ODBC Driver 17 for SQL Server};Server=.\SQLEXPRESS;Database=GameServer;Trusted_Connection=Yes;`)에서 읽습니다 — Windows 통합 인증이라 비밀번호는 없고, 비밀번호가 필요한 DB는 파일 대신 환경변수 `JH_DB_CONNECTION`으로 줍니다(아래 "서버 설정"). 로컬에서 서버를 실행하려면 SQL Server Express(기본 인스턴스명 `SQLEXPRESS`)와 ODBC Driver 17이 설치돼 있고 `GameServer` DB가 있어야 합니다.
- **DB 스키마·SQL 관리 (A2.5, D-150)**: 스키마는 `Server/Resource/DB/`에서 관리합니다. `schema.sql` = 새 DB 생성용(최신 버전 행까지 포함), `migrations/NNNN_<날짜>_<내용>.sql` = 기존 DB를 바꾸는 변경(4자리 순번, 한 트랜잭션, 다시 실행해도 안전하게 `IF NOT EXISTS`, 파일 끝에서 자기 `Schema_Version` 행 INSERT, `USE` 문 없음), `migrate.ps1` = 실행기(`-Status`로 상태만 보기, 기본은 `BACKUP DATABASE` 후 남은 것을 순번대로 적용, `-Server`·`-Database`·`-SkipBackup`). 서버는 마이그레이션을 실행하지 않고, 시작할 때 DB의 `MAX(Schema_Version.Version)`이 `DbQueries::DB_SCHEMA_VERSION`과 다르면 오류를 남기고 시작하지 않습니다(`DatabaseWorker::CheckSchemaVersion`). **테이블·열을 바꿀 때는 마이그레이션 파일 + `schema.sql` + `DB_SCHEMA_VERSION` 증가를 한 커밋에서 함께 합니다.** 서버가 실행하는 SQL 문자열은 전부 `Server/Server/DB/DbQueries.h`에 둡니다(저장 프로시저 없음, `DatabaseWorker`는 바인딩·실행·결과 전달만). 값은 `?` 파라미터로 넘기고 쿼리에 직접 넣는 것은 서버가 검증한 정수뿐입니다.
- **플레이어 저장 (A2.5, D-151)**: 저장은 Room 잡에서 요청하고 `DatabaseWorker`가 실행한 뒤 결과를 Room 잡으로 돌려줍니다. 진행 상황(`Player::progressSave`, 레벨·경험치·HP, `Room::RequestProgressSave`)은 `Player::SaveState`(플레이어당 동시 1건, 진행 중 요청은 합침)로 관리하고, `Player::MakeProgressSnapshot()`이 만든 `DB_PlayerProgress`를 `lastSavedProgress`(DB에 있는 값)와 비교해 **다를 때만** 저장하므로 값을 바꾸는 코드에 변경 표시를 넣지 않습니다. 저장 시점은 주기(`Room::UpdateSaves`, `ServerConfig` `PlayerSaveIntervalSec`)와 방 퇴장이고, 더미 봇(`isDummy`, 전원이 한 행)은 저장하지 않습니다. 저장할 필드를 늘리려면 `DB_PlayerProgress`·`MakeProgressSnapshot`·`DbQueries::UpdatePlayerProgress`·`DatabaseWorker::SavePlayerProgress` 바인딩을 함께 고칩니다. **아이템·골드는 이 스냅숏에 넣지 않습니다**(아래 "아이템 작업").

`ALREADY_DONE`(`ALREADY_ACTIVE`·`NOT_ACTIVE`는 나오지 않음). 수락·완료는 아이템 작업(`ItemOpKind::QuestAccept`·`QuestComplete`)이라 `itemOp` 한 칸을 함께 쓰고(겹치면 `BUSY`) 위 "아이템 작업"의 규칙(DB 성공 뒤 메모리 반영, 롤백 = `DB_ERROR`, 결과 불명 = 접속 끊기, Room 이동·접속 정리가 결과를 기다림)이 그대로 적용됩니다. 요청마다 `Room::CheckQuestRequest`(상점과 같은 순서: 방 안 → 더미 봇 아님 → 생존 → 요청 간격·진행 중인 작업 → 1:1 거래 중 아님 → 퀘스트 NPC → `EconomyTable.ShopRangeCm`)를 거치고, 거부는 `SC_QUEST_RESULT`, 성공은 `SC_QUEST_UPDATE`입니다. 완료(`DbQueries::BuildQuestComplete`)는 상태 → 수집품 회수 → 보상 아이템 → 보상 골드를 한 트랜잭션에 하고 **보상 칸은 회수를 적용한 인벤토리 사본으로 계획**합니다(쿼리도 회수 → 추가 순서 — 바꾸면 칸 유니크 인덱스를 어김). **보상 경험치만은 트랜잭션에 없어**(레벨·경험치는 진행 상황 저장이 통째로 씀) 결과 적용 때 `ApplyExpGain` 뒤 바로 `RequestProgressSave`를 부르고, 결과가 왔을 때 접속이 끊겨 방에 없으면 `Player::AddExp`만 하고 마지막 저장에 싣습니다 — **`ApplyItemOpResult`의 "방에 없으면 건너뜀"을 퀘스트 완료에 그대로 두면 보상 경험치가 사라집니다.** 처치 인정은 `Monster::OnDead`가 `Room::GetKillReceivers`(막타 + 시야 안·생존 파티원)를 한 번 계산해 `GrantKillExp`와 `CreditKill`에 넘기며, **던전 Room에서는 막타와 같은 파티인 그 방의 전원(죽은 사람·시야 밖 포함)**도 인정합니다. 진행은 메모리에 먼저 올리고 바뀔 때마다 `Room::RequestQuestSave`(`Player::questSave` — `RequestProgressSave`와 같은 방식, `UPDATE … WHERE State = 1 AND Progress < ?`라 완료를 덮거나 되돌리지 않음)로 저장합니다. 로그인은 `DatabaseWorker::TryLogin`이 같은 연결의 두 번째 조회(`SelectPlayerQuests`)로 읽고(실패 = `SERVER_ERROR`), 처음 입장 때만 `SC_INVENTORY` 뒤에 `SC_QUEST_LIST`를 보냅니다(Room 이동 때는 다시 보내지 않음). **수령함 알림(D-262)**: 경매 구매 성공(`AuctionService::OnOpDone`)·만료(`OnExpireDone`) 때 `WorldService::NotifySeller`가 접속 중인 판매자에게 `SC_MAIL_NOTICE`를 보내고, 접속하지 않았으면 다음 처음 입장 때 `SelectLogin`의 `HasMail`로 `SC_MAIL_NOTICE(NONE)`을 보냅니다. 지표 `[metrics] quest(total accept/complete/kill/reject save sent/fail inflight)`·`mailNotice` — **접속이 모두 끝난 뒤 `inflight`는 0이어야 정상**입니다. 시험 스크립트는 `load-test` 스킬.
- **포털 이동 (L5, D-203)**: `Room::PlayerUsePortal`은 검증을 통과하면 부활과 같은 순서로 적용합니다: 조준 해제 → 위치 변경(방향 유지·속도 0) → 보정 순번 +1·이동 예산 0 → `SC_TELEPORT`를 **떠나는 자리의** AOI(본인 포함)에 방송 → `UpdateMap`·`UpdateView` → `UpdateDropView`·`UpdateNpcView` → 거래 중이면 거리 검사(`TOO_FAR` 취소). **도착지는 `Room::ResolvePortalTarget` 한 곳에서만 정합니다** — `targetMap`이 이 Room의 레벨이고 `targetPointId`의 포털 마커가 있을 때 그 마커 자리(마커 z = 지면 + 100cm, PlayerStart와 같음)이며, 그 마커의 구역이 이 Room과 같으면 위의 방 안 순간이동(`SameRoom`), 다르면 Room 이동(`OtherRoom` — 위 "구역별 Room·Room 간 이동", `Continent01`의 문 포털은 모두 이쪽)입니다. 다른 레벨로 가는 포털은 그 레벨이 `WorldTable`에 있으면 Room 이동으로 받고(던전 입구 100·던전 출구 — 위 "인스턴스 던전"), 없으면(정거장 110) `SC_MOVE_RESULT(NOT_AVAILABLE)`로 거부합니다. 포털 목록(`SC_PORTAL_LIST`)에는 종류(`PortalKind` — 클라이언트 안내 문구용)가 함께 갑니다. `NavGenerator`는 문을 막아 끊어진 마을 안이 지워지지 않도록 로직 JSON의 `PlayerStart`·같은 레벨 `PortalTrigger` 마커가 놓인 연결 영역을 가장 넓은 영역과 함께 남깁니다(`LoadKeepSeeds`, 출력 `[Prune] 기준점 …`).
- **개발 지급 (A3.3, D-152)**: `CS_DEV_GIVE(item_id, count)`(0 = 골드) → `Room::PlayerDevGive`. `ServerConfig` `[Debug] DevCommands=true`일 때만 받습니다(기본 꺼짐, 꺼져 있으면 `NOT_ALLOWED`). 클라이언트 콘솔 `Give <itemId> <count>`, 봇 `--give-gear`·`--give-interval`·`--slot-interval`(칸 옮기기).
- **중복 접속 차단 (A2.7, D-158)**: `AuthLobby`가 접속 중 캐릭터 목록(`_online`, `PlayerId` → 세션 id·`closing`·대기 로그인 1건)을 갖고 로비 잡 안에서만 읽고 씁니다. 로그인 DB 조회가 성공했는데 목록에 있으면 기존 세션에 `SC_KICK`을 보내고 `Session::ForceClose`로 끊은 뒤, 새 로그인은 대기시켰다가(`HoldLogin`) 이전 접속의 정리가 끝났다는 신호(`OnPlayerClosed`)가 오면 DB 조회부터 다시 합니다 — 방금 읽은 값은 이전 접속의 마지막 저장 전 값일 수 있기 때문입니다. 신호는 `Room::NotifyClosedIfDone`(방에 없음 + 세션 끊김 + DB에 가 있는 작업 0건 = `itemOp`·`progressSave`·`quickSlotSave`·`questSave`, 플레이어당 한 번)과 `GameSession::HandlePlayerGone`(방에 들어가기 전에 끊김)이 `WorldService::OnPlayerClosed`로 보내고, 서비스가 명부·채널 인원을 정리한 뒤 로비로 넘깁니다(DG3a — 더미 봇의 신호는 서비스에서 끝남). **플레이어가 방을 떠나는 경로나 플레이어의 DB 작업(새 저장 종류·아이템 작업)을 추가하면 `NotifyClosedIfDone`의 조건에 넣고 결과 처리 끝에서 불러야 합니다** — 빠지면 그 캐릭터의 다음 로그인이 `LoginCloseForceSec`(30초, ERROR 로그 후 강제 제거)까지 막힙니다. 더미 봇(전원이 한 캐릭터)은 이 목록에 넣지 않습니다(접속자 명부에는 들어감). `[metrics] login(kick/busy/forced)`의 `forced`는 0이어야 정상입니다.

## 알려진 함정 (Gotcha)

세션 중 발견한, 놓치기 쉬운 규칙을 여기에 누적합니다.

- `Room`의 내부 상태는 절대 `PushJob`/`ReserveJob` 밖에서 직접 변경하지 마세요 — 여러 IOCP 워커 스레드가 동시에 접근하는 객체이므로 레이스 컨디션이 발생합니다.
- 플레이어 이동은 `Room::PlayerMove`가 검증합니다(서버 권위 이동, S1 — [Docs/DESIGN_CONTROL_CAMERA.md](../Docs/DESIGN_CONTROL_CAMERA.md)). 검증 허용치는 `MovementTable`의 `Server*` 열, 속도는 스탯 `MoveSpeed`(플레이어 `PlayerStatTable`)입니다. 지형 검사(`NavmeshManager::CanMove`)는 ① 직선 레이캐스트가 끝까지 가거나 막힌 점이 목표에서 `ServerNavToleranceCm` 안이면 통과 ② 막혔어도 목표가 걷는 영역에서 허용치 안이고 걷는 영역 위로 돌아가는 길이 ≤ 이동 거리 + 허용치 × 2이면 통과(L2e, D-186 — 내비메시 경계가 충돌 도형에서 20~55cm 밖이라 장애물에 붙어 도는 캐릭터는 시작점·목표가 모두 경계 밖일 수 있음. 폭 약 60cm 이하 물체는 통과를 막지 못함). 이동 높이 z는 클라이언트 값을 그대로 저장합니다(3m 넘게 어긋난 z를 받으면 이후 이동이 모두 거부됨 — 백로그. 봇은 A5.1부터 내비메시로 바닥 z를 보내고 보정의 z를 받아들임, D-293). 공격 중 이동 잠금(CB1, D-199): `Room::CastSkill`이 시전 확정 때 `Player::BeginMoveLock`을 불러 이동 예산을 정산하고 잠금 끝 시각(`moveLockUntilMs` = 시전 + `SkillTable.MoveLockMs`, 기본 공격은 `AttackSpeed`로 나눔 — `Character::CastTiming.moveLockMs`)을 정한 뒤 예산을 `MovementTable.ServerMoveLockSlackCm`(120cm)로 줄입니다. 봇은 공격하면서 움직여 잠금 중 이동이 보정됩니다(봇 수정은 A5.2). 결과는 `[metrics]`의 `move(total ok/speed/nav/bad/stale/rate)`로 봅니다.

## 서버 설정 (ServerConfig.ini)

운영 값(포트, 바인드 IP, 띄울 레벨 `[World] MapName`(맵 리소스 파일 이름 = `WorldTable.MapName` — 로그인 응답 `map_name`으로 클라이언트에 알림, D-185), 워커 수, 송신·타임아웃·DB·로그 설정 — 전체 키는 `ServerConfig.ini`)은 `Data/ServerConfig`(`GServerConfig`)가 시작할 때 읽습니다. 게임 수치는 여기 두지 않고 DataTable에 둡니다. 우선순위(뒤가 앞을 덮어씀): 코드 기본값 → `Server/Server/ServerConfig.ini`(커밋) → 같은 폴더의 `ServerConfig.local.ini`(있으면, 커밋하지 않음) → 환경변수 `JH_DB_CONNECTION` → 명령줄 `--config <경로>`·`--port <n>`. 설정 파일이 없거나 모르는 키·잘못된 값이 있으면 줄 번호와 이유를 출력하고 시작을 중단합니다. 다른 PC에서 봇을 붙이려면 `BindIp=0.0.0.0`. 부하·시험용 `[Debug]` 키(`DummySpawnZone`·`DummyRoom`·`ViewAudit`·`DbSaveDelayMs`·`MoveHandoffDelayMs`·`DbItemFailEvery`)와 `--roll-drops`는 `load-test` 스킬에 있습니다. 새 키는 `ServerConfig.cpp`의 `ApplyFile`과 `Print`에 추가하고 `ServerConfig.ini`에도 적습니다. INI 파서는 ServerCore `Utils/ConfigFile`(값 뒤 주석은 지원하지 않음).

시작 순서 주의: 시작 실패 시 `exit()`가 전역 소멸자에서 끝나지 않는 스레드(`GTimer`, DB 작업 스레드)를 join하며 멈추므로, 실패할 수 있는 단계(설정 → DataTable → 포트 → DB 연결)를 스레드를 만드는 단계보다 먼저 둡니다.

## 로그 (Logger)

서버 출력은 `cout`/`printf` 대신 ServerCore `Utils/Logger`의 `LOG_DEBUG/INFO/WARN/ERROR("카테고리", "형식 {}", 값)`(std::format 문법)을 씁니다. `CorePch.h`에 들어 있어 어디서나 쓸 수 있습니다. 게임 스레드는 레벨 확인 → 포맷 → 큐에 넣기만 하고 전용 스레드가 콘솔과 `Log.Dir`(기본 `Server/Server/Logs/GameServer_<시작시각>.log`, 커밋 안 됨)에 씁니다. 레벨 기준: 플레이어·연결·패킷마다 남는 로그는 **Debug**(기본 Info에서는 출력 안 됨), 시작·로드·메트릭은 Info, 비정상 입력은 Warn, 실패는 Error. 와이드 문자열은 `Utils::WStringToUTF8`로 바꿔 넘깁니다.

**지표 (`Utils/Metrics`, ServerCore `Network/NetStats`)**: 5초마다 `[metrics]` 로그 한 줄과 작업 폴더의 `metrics.csv` 한 행을 남깁니다. `metrics.csv`의 `run_id` 열은 `Logger::StartStamp()`(로그 파일 이름의 시작 시각)이고, 열을 바꾸면 `Metrics.cpp`의 `CSV_HEADER`와 행 출력을 함께 고칩니다(옛 파일은 서버가 `metrics_old_<run_id>.csv`로 옮김). 열 설명과 측정 자료 보관 규칙은 [Docs/TESTING.md](../Docs/TESTING.md) "부하 테스트 하니스".

**인코딩:** 서버 프로젝트(GameServer·ServerCore·NavGenerator·봇)는 모두 `/utf-8`로 컴파일하고 소스는 UTF-8입니다. 문자열 리터럴·로그 파일·콘솔·클라이언트 문자열(Protobuf)이 모두 UTF-8이므로, 클라이언트 문자열을 `WCHAR`로 바꿀 때는 `CP_UTF8`(또는 `Utils::UTF8ToWString`)을 씁니다(`CP_ACP` 금지).

## 데이터 테이블 (CSV 로더)

서버는 시작할 때 `Common/DataTable/*.csv`를 읽어 스탯/스킬/몬스터/아이템/드랍(`DropTable`)/경제(`EconomyTable`)/스폰(`SpawnTable`)/상점(`ShopTable`)/NPC(`NpcTable`)/퀘스트(`QuestTable`)/이동 검증/시야(AOI) 수치를 로드합니다(규약·컬럼: [Docs/DESIGN_DATA.md](../Docs/DESIGN_DATA.md)). 애셋 참조 컬럼은 서버가 무시합니다. CSV 형식 오류·중복 키·없는 참조가 있으면 서버가 시작을 중단하며, 폴더는 환경변수 `JH_DATA_DIR` 또는 `../../Common/DataTable`에서 찾습니다. 새 테이블은 `DataManager::Init()`에 같은 방식으로 추가합니다.
