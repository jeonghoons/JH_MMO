# Server/CLAUDE.md

이 문서는 `Server/` 디렉토리에서 작업할 때 참고하는 가이드입니다. 프로젝트 전체 구조는 [루트 CLAUDE.md](../CLAUDE.md)를 참고하세요.

## 빌드 & 실행

빌드·실행·종료 절차는 `run-server` 스킬에 있습니다. 솔루션(`Server/Server.sln`, 구성 `Debug|Release` × `x64|x86`)의 다른 실행 프로젝트는 `msbuild Server.sln /p:Configuration=Debug /p:Platform=x64 /t:LoadTest`(`/t:DummyClient`·`/t:NavGenerator`)로 빌드합니다.

- `GameServer` (`Server/Server/Server.vcxproj`) — 실제 게임 서버, 진입점은 `gameserver.cpp`.
- `BotEngine` (`Server/BotEngine/`, 정적 라이브러리) — LoadTest와 DummyClient가 공유하는 봇 엔진. 봇은 클라이언트 측이라 ServerCore를 쓰지 않습니다(DECISIONS 2026-10-30). 프로토콜은 `Server/Server/Protocol/`의 생성 코드를 직접 컴파일하므로 `GanPackets.bat` 뒤에 따로 복사할 것이 없습니다. 새 패킷을 봇이 보내거나 받아야 하면 `BotEngine.cpp`의 `HandlePacket`/`WorkerMain`에 추가합니다.
- `LoadTest` (`Server/LoadTest/`) — BotEngine의 헤드리스 콘솔 프런트엔드. 수치 검증용. 사용법은 [Docs/TESTING.md](../Docs/TESTING.md) 참고.
- `DummyClient` (`Server/DummyClient/`) — BotEngine의 OpenGL 시각화 프런트엔드(시연용). 창을 닫을 때까지 실행. 사용법은 [Docs/TESTING.md](../Docs/TESTING.md) 참고.
- `NavGenerator` (`Server/NavGenerator/`) — Recast/Detour 내비메시 데이터를 오프라인으로 생성하는 도구. **UE에서 맵 지오메트리를 다시 export할 때마다 재실행해야 합니다**(실행법·출력·검증용 `--query` 모드는 `nav-export` 스킬). **`NavmeshManager::CanMove`를 고치면 `NavQuery.cpp`의 `move`도 같이 고칩니다**(두 프로젝트가 코드를 공유하지 않음). 지오메트리는 `Server/MapResource/MapExport.bat <맵>`(UE 커맨드렛 `MapExportCommandlet` → NavGenerator)으로 만들며, **UE에서 캐릭터가 부딪히는 메시와 지형(스태틱메시·ISM·Landscape, 충돌 켜짐 + Pawn Block)만** Detour 좌표(UE (x,y,z) → (y,z,-x), 정점 순서 반대)로 내보냅니다 — 서버 이동 검증이 이 내비메시를 쓰므로 기준이 어긋나면 지나갈 수 있는 곳에서 플레이어가 끌려갑니다(2026-10-30 S1).

서버에는 자동화된 테스트 스위트가 없습니다 — 검증은 `GameServer`를 빌드해서 `LoadTest`/`DummyClient`나 UE 클라이언트로 붙여보는 방식으로 합니다.

프로토콜(생성된 `.pb.h`/`.pb.cc`)은 `Server/Server/Protocol/`에 복사되어 들어옵니다. 이 파일들은 [Common/Protocol/CLAUDE.md](../Common/Protocol/CLAUDE.md)에서 관리하며, 절대 손으로 수정하지 마세요.

## 서버 아키텍처

**계층과 폴더 (2026-10-30 C-5)** — 의존은 GameServer → ServerCore 한 방향입니다.
- **ServerCore는 Protocol·게임 헤더를 include하지 않습니다.** 게임이 필요하면 가상 훅(`Session::OnConnected/OnDisconnected/OnRecvPacket`)이나 주입(`ServerService`의 `SessionFactory`)으로 연결합니다.
- `#include`는 프로젝트 루트 기준 경로로 씁니다(`"Network/Session.h"`, `"Game/Room/Room.h"`). GameServer의 include 경로는 `$(ProjectDir)`와 `$(SolutionDir)ServerCore`이므로 **두 프로젝트에 같은 파일 이름을 만들지 않습니다.** 새 파일은 vcxproj와 `.filters`에 같은 폴더로 추가합니다.

- **Job/JobQueue 패턴** (`Job.h`, `JobQueue.h`): 서버의 동시성 모델입니다. 여러 IOCP 워커 스레드에서 안전하게 접근해야 하는 객체(실제로는 `Room`)는 `JobQueue`를 소유하고, 그 큐에서 실행되는 `Job` 안에서만 자기 상태를 변경합니다(`Room::PushJob` / `Room::ReserveJob`).
- **송신 묶기 (P1b, D-206·D-207)**: 잡 큐(Room·로비)의 작업을 실행 중인 스레드에서 부른 `Session::Send`는 바로 `WSASend`하지 않고 세션 송신 큐에 넣은 뒤 그 잡 큐의 "보낼 세션 목록"(`JobQueue::_pendingSends`, `Session::_flushPending`으로 중복 방지)에 자동 등록됩니다(`JobQueue::Current()` — 잡 큐 밖 스레드의 `Send`는 지금처럼 바로 보냄). **주의**: ① 방 작업 안에서 보낸 패킷은 최대 `SendFlushIntervalMs` 늦게 나갑니다 — 보낸 직후 `Disconnect`하면 버려지므로 끊기 전에 꼭 보내야 하는 패킷은 `Session::ForceClose`(끊기 전에 전송을 걸고 `Disconnect`)를 씁니다. ② **잡 큐(Room)를 없애는 코드를 넣을 때는 먼저 그 큐의 보낼 세션 목록을 모두 내보내는 닫기 절차를 만들어야 합니다** — 목록에 남은 세션은 `_flushPending`이 켜진 채 남아 이후 송신이 조용히 멈춥니다(2026-11-19 리뷰, 지금은 `RoomManager::Remove`를 부르는 곳이 없어 일어나지 않음 — DG3). 지표는 `[metrics]`의 `sendCalls/s`·`bufsPerSend`·`sendPath`·`flushGap`·`sendWake`·`jobWait`(설명 [Docs/TESTING.md](../Docs/TESTING.md) "부하 테스트 하니스").
- **시전 요청·거부 알림 (CP1, D-211·D-213)**: 거부는 `Room::CastSkill`의 `reject` 람다가 플레이어 본인에게만 `SC_ATTACK_RESULT`로 알립니다. 클라이언트는 내 시전을 입력 즉시 시작하고 이 패킷으로 되돌리므로, **`CastSkill`에 거부 조건을 추가하면 조용히 `return`하지 말고 `reject(사유)`를 부릅니다**(빠지면 클라이언트가 2초 동안 다음 시전을 못 보냄). 몬스터는 `seq` 0·허용 오차 0. 봇은 `CS_ATTACK`에 순번을 싣고 거부를 사유별로 셉니다(LoadTest 요약 `[summary] attack:`) — 사냥 봇은 쿨타임을 보지 않아 요청의 약 77%가 거부됩니다(정상).
- **연결 정리 (A5.0, D-220·D-221)**: `Session::Disconnect`는 세션당 한 번만 동작하고 `OnDisconnected` → 세션 목록에서 빼기 → **`shutdown(SD_BOTH)` + `CancelIoEx`** 순서입니다(감사 F4 — 걸려 있던 `WSARecv`·`WSASend`가 세션 참조를 쥐고 있어, 취소하지 않으면 받지 않는 클라이언트의 세션·소켓·송신 큐가 남음). 서버가 스스로 끊는 조건 둘: ① **유휴 타임아웃** — 무엇이든 받으면 `Session::_lastRecvMs`를 갱신하고(`ProcessRecv`), `AuthLobby::CheckIdleSessions`(로비 예약 잡, 5초마다 자기 재예약)가 `ServerService::CloseIdleSessions`로 `[Network] IdleTimeoutSec`(60초, 0 = 끔) 동안 수신이 없던 세션을 끊습니다(로그인 전 연결 포함, 대상을 락 안에서 모으고 락 밖에서 끊음 — `Disconnect`가 `ReleaseSession`의 쓰기 락을 잡음). UE 클라이언트는 5초마다 `CS_PING`(하트비트), 봇은 방에 들어간 뒤 `--ping-interval`(1초)마다 보냅니다 — **클라이언트가 한동안 아무것도 보내지 않는 절차(긴 로딩 등)를 만들면 이 시간보다 짧은지 확인합니다.** ② **송신 큐 상한** — `Session::Send`가 큐에 넣은 뒤 쌓인 수가 `[Network] SendQueueLimit`(4000, 0 = 끔)을 넘으면 WARN 로그를 남기고 끊습니다(핑은 보내면서 받지 않는 클라이언트). 지표 `[metrics] conn(sessionObjs/handles idleKick/sendqKick)`: `sessions`는 `Disconnect` 순간 줄어들므로 끊긴 세션이 실제로 사라졌는지는 `sessionObjs`(살아 있는 `Session` 객체 수 — 바닥은 1, Listener가 다음 접속용을 하나 미리 만듦)·프로세스 핸들 수·`sendQ(total)`로 봅니다.
- **세션 & 패킷**: `GameSession::GetPlayer()`/`SetPlayer()`는 `atomic<shared_ptr>`(로비 잡이 넣고 수신 스레드·`Disconnect`를 부른 스레드가 읽음), 플레이어의 방 `GameObject::GetCurrentRoom()`/`SetOwnerRoom()`은 `atomic<weak_ptr>`입니다. **핸들러 안에서는 한 번만 읽어 지역 변수로 씁니다**(A5.0, 감사 F3·F9).
- **월드 모델·시야(AOI)**: 각 `Room`은 자신의 `GameMap`(`AoiIndex` — 시야는 거리로 판정: 들어옴 ≤ R, 나감 > R+H, 수치는 `WorldTable.csv`)과 `NavmeshManager`를 소유합니다. **위치를 바꾸면 이동이 끝난 뒤 반드시 `UpdateMap`(플레이어 `PlayerMove`, 몬스터 `NPCMove`)을 불러야 합니다** — 늦게 부르면 AOI가 옛 위치를 들고 경계에서 판정이 틀립니다(`[Debug] ViewAudit`로 확인).
- **영속성(Persistence)**: 연결 문자열은 `ServerConfig.ini`의 `[Database] ConnectionString`(기본 `Driver={ODBC Driver 17 for SQL Server};Server=.\SQLEXPRESS;Database=GameServer;Trusted_Connection=Yes;`)에서 읽습니다 — Windows 통합 인증이라 비밀번호는 없고, 비밀번호가 필요한 DB는 파일 대신 환경변수 `JH_DB_CONNECTION`으로 줍니다(아래 "서버 설정"). 로컬에서 서버를 실행하려면 SQL Server Express(기본 인스턴스명 `SQLEXPRESS`)와 ODBC Driver 17이 설치돼 있고 `GameServer` DB가 있어야 합니다.
- **DB 스키마·SQL 관리 (A2.5, D-150)**: 스키마는 `Server/Resource/DB/`에서 관리합니다. `schema.sql` = 새 DB 생성용(최신 버전 행까지 포함), `migrations/NNNN_<날짜>_<내용>.sql` = 기존 DB를 바꾸는 변경(4자리 순번, 한 트랜잭션, 다시 실행해도 안전하게 `IF NOT EXISTS`, 파일 끝에서 자기 `Schema_Version` 행 INSERT, `USE` 문 없음), `migrate.ps1` = 실행기(`-Status`로 상태만 보기, 기본은 `BACKUP DATABASE` 후 남은 것을 순번대로 적용, `-Server`·`-Database`·`-SkipBackup`). 서버는 마이그레이션을 실행하지 않고, 시작할 때 DB의 `MAX(Schema_Version.Version)`이 `DbQueries::DB_SCHEMA_VERSION`과 다르면 오류를 남기고 시작하지 않습니다(`DatabaseWorker::CheckSchemaVersion`). **테이블·열을 바꿀 때는 마이그레이션 파일 + `schema.sql` + `DB_SCHEMA_VERSION` 증가를 한 커밋에서 함께 합니다.** 서버가 실행하는 SQL 문자열은 전부 `Server/Server/DB/DbQueries.h`에 둡니다(저장 프로시저 없음, `DatabaseWorker`는 바인딩·실행·결과 전달만). 값은 `?` 파라미터로 넘기고 쿼리에 직접 넣는 것은 서버가 검증한 정수뿐입니다.
- **플레이어 저장 (A2.5, D-151)**: 저장은 Room 잡에서 요청하고 `DatabaseWorker`가 실행한 뒤 결과를 Room 잡으로 돌려줍니다. 진행 상황(`Player::progressSave`, 레벨·경험치·HP, `Room::RequestProgressSave`)은 `Player::SaveState`(플레이어당 동시 1건, 진행 중 요청은 합침)로 관리하고, `Player::MakeProgressSnapshot()`이 만든 `DB_PlayerProgress`를 `lastSavedProgress`(DB에 있는 값)와 비교해 **다를 때만** 저장하므로 값을 바꾸는 코드에 변경 표시를 넣지 않습니다. 저장 시점은 주기(`Room::UpdateSaves`, `ServerConfig` `PlayerSaveIntervalSec`)와 방 퇴장이고, 더미 봇(`isDummy`, 전원이 한 행)은 저장하지 않습니다. 저장할 필드를 늘리려면 `DB_PlayerProgress`·`MakeProgressSnapshot`·`DbQueries::UpdatePlayerProgress`·`DatabaseWorker::SavePlayerProgress` 바인딩을 함께 고칩니다. **아이템·골드는 이 스냅숏에 넣지 않습니다**(아래 "아이템 작업").
- **아이템 작업 (A3.3, D-153·D-165, 설계 [Docs/DESIGN_ITEMS_TRADE.md](../Docs/DESIGN_ITEMS_TRADE.md))**: 아이템 한 개(스택 한 묶음) = `Player_Item` 한 행(`ItemDbId`), 메모리 사본은 `Player::inventory`(`Game/Item/Inventory`, 인벤토리 + 장착)이고 **권위는 DB**입니다. 아이템·골드의 소유가 바뀌는 동작은 모두 ① Room 잡에서 검증하고 계획(`DB_ItemOp`)을 채움 → ② `Room::StartItemOp`가 `Player::itemOp.inFlight`를 켜고 `DatabaseWorker::ExecItemOp`로 보냄(한 트랜잭션) → ③ `Room::OnItemOpDone`이 성공일 때만 메모리·패킷(`SC_INVENTORY_UPDATE`, 장착이면 `SC_CHANGE_EQUIP` 방송)에 반영하는 순서입니다. 플레이어당 동시에 1건이고 진행 중에 온 요청은 쌓지 않고 `BUSY`로 거부합니다(`Room::CheckItemRequest`, 장착은 `PlayerChangeEquip` 안에서). 결과가 왔을 때 플레이어가 방에 없으면 반영만 건너뜁니다(DB에는 이미 들어갔고 다음 로그인 때 읽음). 골드는 `Gold = Gold + ?`로 증감하고 돌려받은 잔액을 `Player::SetGold`로 넣습니다(메모리에서 더하지 않음, `UpdatedAt`은 건드리지 않음 — NULL이면 "저장한 적 없음"으로 로그인 HP 판단에 씀). SQL은 `DbQueries.h`의 공통 틀(`ItemOpHead`/`ItemOpTail`: TRY 안에서 `BEGIN TRAN` → 문장마다 바뀐 행 수 누적 → 기대와 다르면 롤백, 결과 집합 하나 `Ok, Kind, V`)을 쓰고, **성공 상태 행을 읽었을 때만 성공**으로 봅니다(`DBConnection::Execute`는 배치 첫 문장의 성공만 알려 줌). 모든 UPDATE는 기대 상태(`OwnerId`·`Location`·`EquipSlot`·`Count`)를 WHERE에 적습니다. 자주 쓰는 작업(장착)은 파라미터가 고정된 쿼리(`ItemEquip`), 드문 작업(개발 지급 `BuildItemGive`, 로그인 보정 `BuildItemLoginFix`)은 검증된 정수를 넣어 조립합니다 — 조립식은 요청마다 컴파일이라 DB 실행이 약 5배 느립니다(`TESTING.md` A3.3). 실패는 "롤백 확인(결과 행 `Ok` 0 — `DB_ERROR`만 알림)"과 "불명(실행 오류·결과 행 없음 — DB에 반영됐을 수 있어 접속을 끊고 재로그인으로 다시 읽게 함, `DB_ItemOpResult.unknown`)"으로 나눕니다. **새 아이템 작업을 추가할 때**: `ItemOpKind` + `DB_ItemOp` 필드 + `DbQueries` 쿼리 + `ExecItemOp`의 분기 + `OnItemOpDone`의 분기를 함께 넣고, 요청 핸들러는 `CheckItemRequest` → 검증 → `StartItemOp` 순서를 지킵니다. **인벤토리 칸(A6.1, D-166)**: 인벤토리 행은 칸 번호 `BagSlot`(0부터, 그 밖의 위치는 -1, 유니크 인덱스 `UX_Player_Item_BagSlot`)을 갖고 메모리에서는 `ItemInstance::slot`입니다. 인벤토리로 들어오는 행을 만드는 작업은 `Inventory::FreeSlots`로 빈 칸을 골라 계획에 넣고(`PlanAdd`의 `newSlots`, 장착의 `oldSlot`·`offhandSlot`), 인벤토리 밖으로 내보내는 작업은 `BagSlot`을 -1로 함께 바꿉니다. 장착(`ItemEquip`)과 칸 맞바꿈은 UPDATE 한 문장입니다 — 유니크 인덱스는 문장 끝에 검사하므로 맞바꿈이 중간 상태 없이 되고, 두 문장으로 나누면 어느 순서든 한쪽 인덱스를 어깁니다. `Player_Item`에는 필터 유니크 인덱스(`UX_Player_Item_Equip`·`UX_Player_Item_BagSlot`)가 있어 `QUOTED_IDENTIFIER`·`ANSI_NULLS`가 켜진 연결에서만 쓸 수 있습니다(서버 ODBC·`migrate.ps1`은 켜져 있음, `sqlcmd`로 직접 고칠 때는 `-I`). 지표는 `[metrics] itemOp(sent/fail/busy inflight)`·`itemOpMs`·`equipApplyMs`(장착 요청 → 적용, 기준 p99 50ms — D-163).

## 알려진 함정 (Gotcha)

세션 중 발견한, 놓치기 쉬운 규칙을 여기에 누적합니다.

- `Room`의 내부 상태는 절대 `PushJob`/`ReserveJob` 밖에서 직접 변경하지 마세요 — 여러 IOCP 워커 스레드가 동시에 접근하는 객체이므로 레이스 컨디션이 발생합니다.
- 플레이어 이동은 `Room::PlayerMove`가 검증합니다(서버 권위 이동, S1 — [Docs/DESIGN_CONTROL_CAMERA.md](../Docs/DESIGN_CONTROL_CAMERA.md)). 검증 허용치는 `MovementTable`의 `Server*` 열, 속도는 스탯 `MoveSpeed`(플레이어 `PlayerStatTable`)입니다. 지형 검사(`NavmeshManager::CanMove`)는 ① 직선 레이캐스트가 끝까지 가거나 막힌 점이 목표에서 `ServerNavToleranceCm` 안이면 통과 ② 막혔어도 목표가 걷는 영역에서 허용치 안이고 걷는 영역 위로 돌아가는 길이 ≤ 이동 거리 + 허용치 × 2이면 통과(L2e, D-186 — 내비메시 경계가 충돌 도형에서 20~55cm 밖이라 장애물에 붙어 도는 캐릭터는 시작점·목표가 모두 경계 밖일 수 있음. 폭 약 60cm 이하 물체는 통과를 막지 못함). 이동 높이 z는 클라이언트 값을 그대로 저장합니다(3m 넘게 어긋난 z를 받으면 이후 이동이 모두 거부됨 — 백로그). 공격 중 이동 잠금(CB1, D-199): `Room::CastSkill`이 시전 확정 때 `Player::BeginMoveLock`을 불러 이동 예산을 정산하고 잠금 끝 시각(`moveLockUntilMs` = 시전 + `SkillTable.MoveLockMs`, 기본 공격은 `AttackSpeed`로 나눔 — `Character::CastTiming.moveLockMs`)을 정한 뒤 예산을 `MovementTable.ServerMoveLockSlackCm`(120cm)로 줄입니다. 봇은 공격하면서 움직여 잠금 중 이동이 보정됩니다(봇 수정은 A5.2). 결과는 `[metrics]`의 `move(total ok/speed/nav/bad/stale/rate)`로 봅니다.

## 서버 설정 (ServerConfig.ini)

운영 값(포트, 바인드 IP, 띄울 레벨 `[World] MapName`(맵 리소스 파일 이름 = `WorldTable.MapName` — 로그인 응답 `map_name`으로 클라이언트에 알림, D-185), 워커 수, 송신·타임아웃·DB·로그 설정 — 전체 키는 `ServerConfig.ini`)은 `Data/ServerConfig`(`GServerConfig`)가 시작할 때 읽습니다. 게임 수치는 여기 두지 않고 DataTable에 둡니다. 우선순위(뒤가 앞을 덮어씀): 코드 기본값 → `Server/Server/ServerConfig.ini`(커밋) → 같은 폴더의 `ServerConfig.local.ini`(있으면, 커밋하지 않음) → 환경변수 `JH_DB_CONNECTION` → 명령줄 `--config <경로>`·`--port <n>`. 설정 파일이 없거나 모르는 키·잘못된 값이 있으면 줄 번호와 이유를 출력하고 시작을 중단합니다. 다른 PC에서 봇을 붙이려면 `BindIp=0.0.0.0`. 부하·시험용 `[Debug]` 키(`DummySpawnZone`·`ViewAudit`·`DbSaveDelayMs`·`DbItemFailEvery`)와 `--roll-drops`는 `load-test` 스킬에 있습니다. 새 키는 `ServerConfig.cpp`의 `ApplyFile`과 `Print`에 추가하고 `ServerConfig.ini`에도 적습니다. INI 파서는 ServerCore `Utils/ConfigFile`(값 뒤 주석은 지원하지 않음).

시작 순서 주의: 시작 실패 시 `exit()`가 전역 소멸자에서 끝나지 않는 스레드(`GTimer`, DB 작업 스레드)를 join하며 멈추므로, 실패할 수 있는 단계(설정 → DataTable → 포트 → DB 연결)를 스레드를 만드는 단계보다 먼저 둡니다.

## 로그 (Logger)

서버 출력은 `cout`/`printf` 대신 ServerCore `Utils/Logger`의 `LOG_DEBUG/INFO/WARN/ERROR("카테고리", "형식 {}", 값)`(std::format 문법)을 씁니다. `CorePch.h`에 들어 있어 어디서나 쓸 수 있습니다. 게임 스레드는 레벨 확인 → 포맷 → 큐에 넣기만 하고 전용 스레드가 콘솔과 `Log.Dir`(기본 `Server/Server/Logs/GameServer_<시작시각>.log`, 커밋 안 됨)에 씁니다. 레벨 기준: 플레이어·연결·패킷마다 남는 로그는 **Debug**(기본 Info에서는 출력 안 됨), 시작·로드·메트릭은 Info, 비정상 입력은 Warn, 실패는 Error. 와이드 문자열은 `Utils::WStringToUTF8`로 바꿔 넘깁니다.

**지표 (`Utils/Metrics`, ServerCore `Network/NetStats`)**: 5초마다 `[metrics]` 로그 한 줄과 작업 폴더의 `metrics.csv` 한 행을 남깁니다. `metrics.csv`의 `run_id` 열은 `Logger::StartStamp()`(로그 파일 이름의 시작 시각)이고, 열을 바꾸면 `Metrics.cpp`의 `CSV_HEADER`와 행 출력을 함께 고칩니다(옛 파일은 서버가 `metrics_old_<run_id>.csv`로 옮김). 열 설명과 측정 자료 보관 규칙은 [Docs/TESTING.md](../Docs/TESTING.md) "부하 테스트 하니스".

**인코딩:** 서버 프로젝트(GameServer·ServerCore·NavGenerator·봇)는 모두 `/utf-8`로 컴파일하고 소스는 UTF-8입니다. 문자열 리터럴·로그 파일·콘솔·클라이언트 문자열(Protobuf)이 모두 UTF-8이므로, 클라이언트 문자열을 `WCHAR`로 바꿀 때는 `CP_UTF8`(또는 `Utils::UTF8ToWString`)을 씁니다(`CP_ACP` 금지).

## 데이터 테이블 (CSV 로더)

서버는 시작할 때 `Common/DataTable/*.csv`를 읽어 스탯/스킬/몬스터/아이템/드랍(`DropTable`)/경제(`EconomyTable`)/스폰(`SpawnTable`)/상점(`ShopTable`)/NPC(`NpcTable`)/이동 검증/시야(AOI) 수치를 로드합니다(규약·컬럼: [Docs/DESIGN_DATA.md](../Docs/DESIGN_DATA.md)). 애셋 참조 컬럼은 서버가 무시합니다. CSV 형식 오류·중복 키·없는 참조가 있으면 서버가 시작을 중단하며, 폴더는 환경변수 `JH_DATA_DIR` 또는 `../../Common/DataTable`에서 찾습니다. 새 테이블은 `DataManager::Init()`에 같은 방식으로 추가합니다.
