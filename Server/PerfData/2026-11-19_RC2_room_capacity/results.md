# RC2 Room 수용 인원 재측정 (2026-11-19, P1b 뒤)

송신 묶기(P1b, D-206·D-207)가 들어간 빌드로 500m `Continent01`의 Room 하나가 몇 명을 받는지 다시 쟀습니다. 이전 측정은 `../2026-11-17_room_capacity/`(300m 레벨, P1 전, `DESIGN_WORLD.md` §14-3).

## 환경
- PC i5-10400F(6코어 12스레드), 서버·봇 같은 PC, Release x64, 에디터 닫음. 빌드: 작업 트리(커밋 전, 직전 커밋 `c7b74a0` + P1b).
- 레벨 `Continent01`(504m, 몬스터 201마리), **Room 하나**(임시 DataTable `datatable/`에서 `RoomCapacity`만 1000 — 저장소 CSV는 그대로), 워커 6(기본), `SendFlushIntervalMs` 10, `TimerResolutionMs` 1.
- 봇: `--ramp-rate 50 --threads 4 --move-interval 200 --body male --duration 75`. 수치는 접속이 끝나고 10초 뒤부터.
- 배치: 분산 = 레벨 전체 무작위 / 밀집 = 광장 반경 10m(`-14200,0,1000`) / 마을 = 마을 평지 전체(중심 (-150m, 0) 반경 68m, `-15000,0,6800`) / 전투 = 분산 + `--profile hunt`.
- 실행 이름 `<배치>_<인원>_r<회차>`, 각 2회. 유휴(`idle`, 봇 1명) 틱 지연 p99 2ms.

## 읽은 것
1. **통과 인원은 분산 250명입니다**(전투 포함도 통과, 여유 있음). 375명은 틱 지연만 21~27ms로 조금 넘고, 500명은 틱 지연 34~35ms입니다.
2. **넘어도 무너지지 않습니다.** P1 전에는 분산 500명·밀집 150명이 붕괴(핑 수천~수만 ms, 송신 6.5만 건/s에서 멈춤)였는데, 지금은 분산 500명 핑 35~40ms, 밀집 250명 핑 37~48ms입니다. 마을에 500명이 다 모여도(시야 안 365명, 송신 87만 건/s) 핑 125~132ms로 버팁니다.
3. **지금 걸리는 지표는 거의 틱 지연 p99 하나입니다.** 핑은 마을 250명 이상에서만 넘고, 틱 본문은 전부 4ms 아래입니다.
4. **방 스레드는 한가합니다**(대부분 9~19%, 마을 500명만 33~35%). 그런데 작업이 큐에서 기다린 시간은 p50 2~13ms, p99 25~40ms입니다. 평균 점유가 낮은데 대기가 긴 것이라 일이 고르게 오지 않고 몰려서 온다는 뜻입니다. 세션 송신 간격 p90이 95~127ms인 것도 같은 방향입니다(방이 100ms쯤 조용했다가 한꺼번에 처리). **몰림의 원인은 확인하지 못했습니다** — 후보는 ① 봇 프로그램이 이동 패킷을 묶음으로 보냄(같은 PC·스레드 4개, 측정 도구의 특성) ② 서버 쪽 수신·작업 처리의 몰림. ①이면 실제 클라이언트에서는 틱 지연이 이보다 낮을 것이고 ②면 고칠 대상입니다.
5. **받는 쪽 한계는 그대로입니다.** 봇 수신은 시야 안 1명당 약 0.42KB/s라 한 화면 약 150명에서 64KB/s에 닿습니다(밀집 150명 63, 마을 250명 100). 송신 묶기와 무관하며 푸는 방법은 표시 정책(가까운 N명만)입니다.
6. **500m 레벨의 시야 안 인원은 인원 × 약 0.043입니다**(250명 11, 375명 16, 500명 22 — 300m 때는 × 0.11). 마을에 모이면 인원 × 약 0.72(150명 107, 250명 179)로, `DESIGN_WORLD.md` §15의 계산(150명이 고르게 있으면 약 60명)보다 큽니다 — 봇이 원 안의 임의 지점을 오가며 가운데에 몰리기 때문입니다.
7. **2026-11-18의 "워커 1 추정"과 비교**: 분산 250명은 추정(핑 37~45ms)보다 좋고(20~23ms), 밀집 150명은 추정(틱 지연 9ms, 통과)보다 나쁩니다(27~31ms). 레벨 크기와 몬스터 수가 달라 정확한 비교는 아닙니다.

## 측정의 한계
같은 PC에서 봇을 돌렸고(봇 CPU는 코어 1의 20~71%), 반복은 2회입니다. 마을·사냥터 혼합 배치와 Room 여러 개는 재지 않았습니다. 틱 지연 원인(위 4번)은 지표로 본 추정입니다.
