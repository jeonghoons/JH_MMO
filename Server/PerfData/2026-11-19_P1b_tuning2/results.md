# P1b 송신 간격(T) 고르기 — 2차 측정 (2026-11-19)

원인 조사(`../2026-11-19_P1b_cause/results.md`)의 수정 세 가지(타이머 해상도 1ms, 내보내기를 16개씩 워커로 넘김, 완료 직후 재전송 건너뜀)를 넣은 빌드로 T를 다시 쟀습니다.

## 환경
- PC i5-10400F, 서버·봇 같은 PC, Release x64, 에디터 닫음. 빌드: 작업 트리(커밋 전) + 직전 커밋 `c7b74a0`.
- 레벨 `Continent01`, `RoomCapacity` 100, 워커 6(기본), `TimerResolutionMs` 1. 봇 인자는 P1a 기준선과 같음. 핫존 = `-14200,0,1000`.
- 실행 이름 `<시나리오>_t<T>_r<회차>`, 조합마다 2회(회차를 바깥 반복으로 돌려 시간에 따른 PC 상태 변화를 T마다 고르게 섞음).
- "수정 전"은 같은 날 오후에 P1b 전 exe로 다시 잰 값(`../2026-11-19_P1b_cause/`의 `pre`)이고, 핫존 25·50은 오전 P1a 기준선 값입니다. 이날 오후는 오전보다 CPU가 높게 나오는 상태였습니다(분산 1,000 수정 전 88~102 → 140~143).

## 읽은 것
- **32회 모두 기존 합격선(D-057) 통과**, 접속 실패·예상 밖 종료 0, 서버 WARN·ERROR 0.
- **한산~중간 밀도에서 핑 p99는 거의 "T + 2~3ms"입니다**(핫존 25·50: 7~8 / 12~13 / 17~18 / 22~24). 묶는 시간이 그대로 응답 지연에 더해집니다 — T를 작게 잡을 이유.
- **핫존 100의 CPU는 T=10이 가장 낮습니다**(27~32). T=5는 호출 수가 늘어 36~49, T=20은 예상과 달리 호출 수가 T=10·15보다 많아(초당 약 2,870회, 호출당 16건) 38~40입니다. T=20에서는 세션 송신 간격이 22ms 근처로 고르게 나오고, T=10·15에서는 봇 패킷이 몰려 들어와 100ms 넘는 공백이 섞이면서 한 번에 더 많이 실립니다 — 즉 T=10·15의 높은 묶임은 일부 봇 도착 양상 덕입니다.
- **핫존 100 CPU는 어느 T에서도 목표 25%에 들지 못했습니다**(가장 낮은 값 27~32%, 수정 전 78~80%). 지연·묶임 목표는 T=5~20 모두 충족.
- 분산 1,000은 회차 간 편차가 커서(T=5: 14 대 29) T 사이의 차이를 가를 수 없습니다. 모든 T에서 목표(≤ 40)는 충족하고 수정 전(21~23)과 비슷한 범위입니다.
