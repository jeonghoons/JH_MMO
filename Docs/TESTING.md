# 수동 테스트 절차

서버에는 자동화된 테스트 스위트가 없습니다. 아래는 봇(`LoadTest` 콘솔, `DummyClient` 시각화 — 둘 다 같은 `BotEngine`)으로 서버 로직을 수동 검증하는 절차입니다. 아키텍처/빌드 전반은 [Server/CLAUDE.md](../Server/CLAUDE.md)를 참고하세요.

## 기본 절차

1. `GameServer`를 빌드하고 실행합니다: `msbuild Server.sln /p:Configuration=Debug /p:Platform=x64 /t:GameServer`
2. 수치 검증은 `LoadTest`(아래), 눈으로 보는 확인·시연은 `DummyClient`를 빌드해 `Server/Server` 폴더에서 실행합니다: `..\x64\Release\DummyClient.exe --bots 100 --ramp-rate 20 --profile hunt [--hero archer] [--chaos]`. 인자는 LoadTest와 같고(`--duration`·`--out`은 무시, 창을 닫을 때까지 실행), 창에 봇(초록)·시야 안 몬스터(빨강, 죽으면 회색)·몬스터 스폰(주황 +)·통계(접속/로그인 실패, 핑 p50/p95/p99, 패킷/초, 서버 CPU·메모리, 처치 수)가 보입니다. 휠 = 확대/축소, 드래그 = 이동, F = 전체 맞춤, Esc = 종료. 종료 시 콘솔에 실패 집계가 찍힙니다.
3. 서버 콘솔/로그에서 접속·이동·전투 등 확인하려는 패킷 흐름을 관찰합니다.

## 부하 테스트 하니스 (LoadTest)

`Server/LoadTest` — 헤드리스 콘솔 봇 클라이언트(봇 동작은 `Server/BotEngine`, `DummyClient`가 같은 엔진의 시각화 화면). 서버의 `metrics.csv`/콘솔 `[metrics]` 줄과 함께 본다.

```
msbuild Server.sln /p:Configuration=Release /p:Platform=x64 /t:GameServer
msbuild Server.sln /p:Configuration=Release /p:Platform=x64 /t:LoadTest
cd Server\Server && ..\x64\Release\GameServer.exe          # 서버 (SQL Server Express 필요)
#   설정: Server/Server/ServerConfig.ini (포트·DB·스레드·로그 레벨). 임시 변경은 --port <n>, --config <경로>, 개인 PC 값은 ServerConfig.local.ini
..\x64\Release\LoadTest.exe --bots 1000 --ramp-rate 200 --duration 60 --threads 4
```

| 옵션 | 기본 | 설명 |
|---|---|---|
| `--bots` | 100 | 봇 수 |
| `--ramp-rate` | 50 | 초당 접속 시도 수(램프업) |
| `--duration` | 60 | 램프 시작부터 종료까지 전체 시간(초) |
| `--threads` | 4 | 워커 스레드 수 |
| `--profile` | move | `move`(이동+핑) / `idle`(핑만) / `hunt`(몬스터 스폰으로 이동해 공격·스킬 사용) |
| `--body` | male | 체형. `male`(dummy 계정 로그인 — 맵 전체 무작위 배치) / `female`(`fem_*` 계정 가입 후 로그인 — PlayerStart에서 시작). 2026-11-07 MC3.1에서 `--hero warrior\|archer`를 대체. 무기는 MC3.2 전까지 없음(맨손 기본 공격만, 1번 슬롯은 서버가 거부) |
| `--chaos` | 끔 | 공격 요청의 일부를 일부러 잘못된 값으로 보냄(오류 테스트) |
| `--equip-interval` | 0(끔) | 이 간격(ms, ±50%)마다 무작위 장비 교체 요청(천·판금·해제, 10%는 연타). 장비 저장 측정용. 기본 장비가 있는 개별 계정이 필요하므로 `--body female`과 함께 쓴다(dummy는 모든 봇이 한 캐릭터를 공유) |
| `--map` | 자동 | hunt용 맵 로직 JSON 경로(몬스터 스폰 위치). 생략하면 `../../MapResource/...`를 찾음 |
| `--move-interval`, `--ping-interval` | 1000 | ms |
| `--host`, `--port` | 127.0.0.1, 8888 | 서버 주소 |
| `--out` | loadtest_<time>.csv | 5초 간격 결과 CSV |
| `--server-proc` | GameServer.exe | CPU/메모리를 샘플링할 서버 프로세스 이름 |
| `--zone x,y,r` | 끔 | 핫존: 봇이 (x,y) 반경 r(cm) 안에서만 움직인다(밖이면 중심으로 걸어감). 봇을 처음부터 그 안에 두려면 서버 `ServerConfig.ini` `[Debug] DummySpawnZone=x,y,r`을 같이 준다(더미 로그인만 적용) |

- CSV 열: `t_sec, connected, in_game, connect_fail, unexpected_close, login_p50/p95, ping_p50/p95/p99/max, sent_ps, recv_ps, recv_kbps(전체, kbit/s), move_corrected, server_cpu_pct, server_mem_mb, max_bot_recv_KBps`(구간에서 가장 많이 받은 봇 1명의 수신량, KB/s — 합격선 64KB/s), `bot_cpu_pct`(LoadTest 프로세스 CPU — 봇 쪽 한계 구분용).
- 실제 클라이언트는 이동을 200ms마다 보낸다(`MovementTable.MoveSendIntervalMs`) — 부하 측정은 `--move-interval 200`으로 한다(A1.3부터).

- 봇은 `CS_LOGIN`(`is_dummy`) → `CS_ENTER_ROOM` → 주기적 `CS_MOVE` / `CS_PING`을 보낸다. 핑 RTT는 서버 Room의 JobQueue를 거쳐 응답되므로 Room 처리 지연이 포함된다.
- 현재 봇 로그인은 서버가 `dummy` 계정으로 치환한다(A5.1에서 제거 예정).
- 서버 지표(`[metrics]` 로그 줄 5초마다, `Server/Server/metrics.csv`는 앞쪽 일부 열만): `sessions, rooms, players, in/s, out/s`, `tickLate`(예정 대비 지연)·`tickBody`(Update 처리 시간)의 avg/p50/p95/p99/max(ms, 틱마다 표본), `viewPlayers`/`viewObjects`(플레이어 1명의 시야 안 플레이어 수/전체 오브젝트 수 avg/p99/max, 1초마다 표본), `sendQ(total/sessionMax)`(송신 큐에 쌓인 패킷: 전체 현재값/구간 중 한 세션 최대), `logDrop`. 합격선(DECISIONS 2026-10-31): 틱 본문·지연 p99 ≤ 20ms, 핑 p99 ≤ 50ms, 봇 1명 수신 ≤ 64KB/s, 송신 큐 꾸준한 증가 없음, 서버 CPU ≤ 70%, 실패·logDrop 0.
- 악성 패킷 주입은 PowerShell 원시 소켓으로 수행했다(결과는 아래 기록). 한 PC에서 서버와 LoadTest를 같이 돌리면 CPU를 공유하므로 보고서에 명시한다.
